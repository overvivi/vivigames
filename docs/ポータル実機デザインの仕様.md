# ポータル実機デザインの仕様

`index.html`（ゲーム置き場）を、**中央に据えた1台の実機へカセットを挿す**形へ作り替える。

試作: `portal-prototype.html`（ブラウザで開けば動く。まだ未リンク）

## なぜ変えるか

いままではゲームごとにアーケード筐体の絵を1台ずつ用意していた。
筐体は3D・陰影・パース・金属の質感を持つので、**生成AIに同じ型を再現させられない。**
新作のたびに違うデザインの筐体が並び、作り直しになっていた。

実機＋カセット方式なら、**立体物は最初の1回しか作らない。**
ゲームごとに増えるのは平らなラベルの絵だけで、これは生成AIが安定して量産できる。

---

## 発注の大原則

### 原則1: 機能する部品はAIに描かせない

差込口・表示窓・ランプ・PLAYボタンは**すべてHTML/CSSで上から描く。**
AIには「そこに何も置いていない平らな面」だけ確保してもらう。

こうする理由は、生成AIが座標を指定どおりに描けないため。
絵の中に差込口が描かれていると、カセットの落下位置と1ピクセル単位で
合わせる必要が出て、ズレると操作感が崩れる。**描かせなければズレようがない。**

### 原則2: 文字は一切描かせない

タイトルもロゴもHTML側で描く。生成画像の文字は毎回崩れる。

### 原則3: 光らせない

ランプもネオンも消灯した状態で描かせる。点灯はCSSでゲームごとの色を乗せる。
最初から光っていると色が混ざって濁る。

### 原則4: 位置は「だいたい」でよい

大きさや位置のズレは、こちらでCSS変数を詰めれば吸収できる。
**AIに完璧な座標を求めない。** 求めるのは下の「絶対条件」だけ。

## 1. 実機本体 `console-body.png`（1600 × 900）

現実には存在しない、アーケードの匂いがする据置ゲーム機。
ファミコンや64のような「横長で低い箱」の骨格に、業務用機の重さを足す。

### 絶対条件（外れたら作り直し。後から直せない）

1. **背景が完全に透過している**
2. **文字・数字・ロゴが1つも無い**
3. **ランプやLEDが光っていない**（すべて消灯）
4. **上面の中央が平ら**で、そこに何も乗っていない
   → 幅は本体の3割ほど、奥行きも十分に取る。ここへ差込口を描く
5. **前面に、横長で平らな暗い面がある**
   → 本体幅の7割ほど。ここへ表示窓を描く。模様も部品も置かない
6. **本体が画像の枠内に収まっている**（脚まで含めて見切れていない）
7. 色が**無彩色寄り**（ガンメタル〜黒）
   → どのゲームの色を乗せても喧嘩しないため。青や赤に寄せない

### だいたいでよいこと（こちらで詰める）

- 上面の空き地や前面の面の**正確な位置とサイズ**
- 本体の傾き、パースの強さ
- 放熱スリット、補強、脚などの装飾の配置

### 指示文（そのまま貼れる）

```
架空の据置ゲーム機を描いてください。1600×900ピクセル、背景は完全透過のPNG。

構図:
・正面やや上から見下ろした角度。上面と前面の両方が見えていること
・機体は横長で低い箱型。ファミコンや初期の家庭用ゲーム機の骨格に、
　業務用アーケード機材の重厚さを足したデザイン
・脚まで含めて機体全体が画像の中に収まること。見切れさせない

必ず空けておく場所（ここに何も置かないでください）:
・上面の中央に、幅が本体の3割ほどの平らな空き地。
　ボタン、模様、装飾を一切置かない
・前面に、幅が本体の7割ほどの横長で平らな暗い面。
　ここにも部品、模様、装飾を一切置かない

自由に描いてよい場所:
・側面の放熱スリット、角の金属補強、下部の太い脚、
　筐体の分割線やネジ、使い込まれた傷や指紋の質感

質感と色:
・ガンメタルから黒の無彩色。金属とスモークアクリル
・青や赤などの色味に寄せないこと

絶対に守る条件:
・ランプやLEDは一切光らせず、すべて消灯した状態で描く
・文字、数字、ロゴ、メーカー名を一切描かない
・背景は完全透過。影は本体の真下にごく薄くだけ

写実的な3DCG風。
```

### 受け取り時の確認

- [ ] 背景が透過になっているか（白い板が付いていないか）
- [ ] どこにも文字が入っていないか
- [ ] ランプが光っていないか
- [ ] 上面の中央が平らで、何も乗っていないか
- [ ] 前面に横長の平らな暗い面があるか
- [ ] 脚まで収まっていて見切れていないか

## 2. カセットの殻 `cartridge-shell.png`（600 × 800）

全ゲームで使い回す**空のカセット**。ラベルはこちらで上から重ねる。

### 絶対条件

1. **背景が完全に透過している**
2. **文字・ロゴが1つも無い**
3. **中央に無地の四角い面がある**（模様も絵も描かない）
   → ほぼ正方形。カセットの横幅いっぱいではなく、左右に樹脂の縁を残す
4. 色が**無彩色**（濃いグレーの樹脂）。特定のゲームの色に寄せない
5. **正面から見た構図**（斜めから見ない）
   → 実機に挿したとき、本体の角度と食い違って見えるため

### 指示文

```
架空のゲーム機用カセット（カートリッジ）を描いてください。
600×800ピクセル、背景は完全透過のPNG。

・真正面から見た構図。斜めから見ない
・縦長の長方形。上部に厚みのある持ち手のリブ、下部に端子の切り欠き
・中央に、ラベルを貼るための無地の四角い面がある。
　ほぼ正方形で、左右には樹脂の縁が残る幅
・その面の中には、模様も絵も文字も一切描かない（無地の暗いグレー）
・材質は濃いグレーの樹脂。角に成型の跡や小さな傷
・色は無彩色のみ。特定の色に寄せない
・文字、数字、ロゴを一切描かない
・背景は完全透過

写実的な3DCG風。
```

### 受け取り時の確認

- [ ] 背景が透過か
- [ ] 真正面からの構図か（斜めになっていないか）
- [ ] 中央の面が完全に無地か
- [ ] 文字が無いか
- [ ] 色が無彩色か（青や紫に寄っていないか）

## 3. ラベルの絵（800 × 800・ゲームごと）

カセットの中央に貼る絵。**ここだけがゲームごとに増える。**

### 絶対条件

1. **正方形**
2. **文字・数字・ロゴが1つも無い**（タイトルはHTML側で重ねる）
3. **絵がふちまで続いている**（余白・額縁・枠を作らない）
   → こちらで四隅を丸く切るので、端に大事なものを置かない
4. **平面のイラスト**として描く
   → カセットや紙として立体的に描かない。影も付けない（こちらで付ける）
5. 主役が**中央寄り**にある
   → 小さく表示されるので、端に置くと何か分からなくなる

### 3本ぶんの内容

| ゲーム | 描くもの | 色 |
|---|---|---|
| HELL RUNNER | 崩れた足場を走る骸骨。背後に炎と荒れた空、追うデビルの影 | 赤・橙・黒 |
| 討伐2048 | 光る数字タイルの盤面と、奥にそびえる巨大な魔王 | 紫・青 |
| HEXAMINE | 六角形のマスが敷き詰められた盤面。一部がシアンに発光し、奥に分子構造 | シアン・マゼンタ |

### 指示文（HEXAMINEの例。内容の段落だけ差し替えて使う）

```
800×800ピクセルの正方形イラストを描いてください。

内容:
六角形のマスが敷き詰められたパズル盤面を、やや斜め上から見た構図。
いくつかのマスがシアン(#20e6ff)に強く発光し、残りのマスは黒く沈んでいる。
盤面の奥に、六角形が結びついた分子構造の模式図がぼんやり光っている。
差し色にマゼンタ(#ff2ba6)を少しだけ使う。

条件:
・文字、数字、ロゴを一切描かない
・絵はキャンバスのふちまで続かせる。余白、額縁、枠を作らない
・主役は中央寄りに置く。小さく表示されるため、端に置くと読み取れない
・平面のイラストとして描く。カセットや紙として立体的に描かない。影も付けない
・全体は暗く、発光している部分だけが際立つ配色
```

### 受け取り時の確認

- [ ] 正方形か
- [ ] 文字が無いか（**AIが一番よく入れてくる**）
- [ ] ふちまで絵が続いているか（白フチや額縁が付いていないか）
- [ ] 立体的に描かれていないか（紙やカセットとして描かれていないか）
- [ ] 主役が中央寄りか

## 画面の作り

```
        ┌────┐ ┌────┐ ┌────┐ ┌────┐
        │HELL│ │BOSS│ │HEXA│ │ ?  │   ← カセット置き場
        └────┘ └────┘ └────┘ └────┘
                    │ 選んだものが下りてくる
                    ▼
        ╔═══════════════════════╗
        ║  ▁▁▁▁▁ ← 差込口(CSS)  ║
        ║  ┌─────────────────┐  ║
        ║  │ HEXAMINE   PLAY │  ║   ← 表示窓(CSS)
        ║  └─────────────────┘  ║
        ╚═══════════════════════╝
```

- カセットを押すと、**上から差込口へ下りて挿さる**
- 挿さると表示窓が**そのゲームの色で点灯**し、タイトル・一行説明・PLAYが出る
- PLAYでゲームへ移動する
- 取り出したカセットは、置き場に**空のくぼみ**として残す（列に穴が空かないように）

### 実装で守ること（試作で対応済み）

- カセットは `<button>`、PLAYは `<a>`。**キーボードだけでも辿れる**
- 挿す演出は400ms。**演出中でもPLAYは押せる**（待たせる理由が無い）
- 「動きを減らす」設定では演出を飛ばす
- 携帯では表示窓の中身を縦積みにし、窓自体を広げる
- COMING SOONは押しても挿さらず、いま挿さっているゲームも外さない

## 画像が届いてからの作業

1. PNG → webp へ変換して `images/portal/` へ配置
2. 試作の仮図形を画像に差し替える
3. **差込口と表示窓の位置をCSS変数で詰める**

```css
--slot-x  / --slot-y            /* 差込口の中心 */
--panel-x / --panel-y           /* 表示窓の左上 */
--panel-w / --panel-h           /* 表示窓の大きさ */
--label-x / --label-y           /* カセットのラベル位置 */
--label-w / --label-h
```

絵の空き地がどこに来ても、この6〜10個の数字を測って入れれば合う。
**絵を描き直させる必要は無い。**

4. 問題なければ `index.html` を置き換える
5. パッチノートに追記し、`npm run verify` で素材の参照漏れを検査

**試作が固まるまで `index.html` は触らない。** 公開中のため。

## 生成AIがよく外すところ

経験上、指示しても以下は高確率で無視される。**毎回目視で確認する。**

| 外れること | どうなるか |
|---|---|
| 背景の透過 | 白や黒の板が付いてきて、四角く浮いて見える |
| 「文字を描かない」 | 勝手にメーカー名やタイトルを入れてくる |
| 「光らせない」 | ネオンを盛ってきて、CSSの色と混ざって濁る |
| 「空き地を作る」 | 上面にボタンや模様を置いてしまい、カセットが重ねられない |
| ラベルの「額縁を作らない」 | 白フチや紙の質感を付けてきて、くぼみに収まらない |

サイズが違っても縦横比が合っていれば使える。**縦横比だけは守らせる。**
