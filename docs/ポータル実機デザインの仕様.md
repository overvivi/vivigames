# ポータル実機デザインの仕様

`index.html`（ゲーム置き場）を、**1台の携帯機へゲームのデータを流し込む**形へ作り替える。

試作: `portal-prototype.html`（ブラウザで開けば動く。まだ未リンク）

## いま発注が要るのは1枚だけ

| ファイル | サイズ | 何回作るか |
|---|---|---|
| `console-body.png` | 1600 × 760 | **一度だけ** |

カセットはCSSで描いているので**画像は要らない**。
ゲームごとに要るのは**画面へ出す絵1枚**だけ。これはCSSカセット内にも同じ絵を小さく表示する。既存3本ぶんに加え、HELL RUNNER 2 β用は`cart-label-hell-runner-2-beta`として追加済み。

## ここまでの経緯（同じ失敗を繰り返さないため）

**筐体を1台ずつ用意する形は捨てた。** 3D・陰影・パース・金属の質感を持つ絵は、
生成AIに同じ型を再現させられない。新作のたびに違う筐体が並ぶことになっていた。

**据置機＋携帯機用カセットも捨てた。** 縮尺が食い違って見えた。
PSシリーズのような本体にゲームボーイのカセットを挿す絵になっていた。

**カセットの絵も捨てた。** CSSで描いたほうが、形も色も光り方も後から変えられる。
実際、初代GBの縦長からGBAのほぼ正方形（35×32mm）へ直したときも、
画像を作り直さず数値を変えるだけで済んだ。

**ラベルは描き直さない。** 届いた絵は原寸で見れば十分に強く、
90pxのカセットに貼るから読めなかっただけ。**画面へ大きく出す**ことで解決した。

## ゲームの絵を発注するときの必須条件

**新作を足すとき、これだけは守る。** 絵そのものは自由でよいが、
下側に主役を置くと本体の画面で切れる。

### 1枚の絵を、2か所で違う切り取り方をして使う

| 表示場所 | 見え方 |
|---|---|
| カセット（置き場） | **正方形のまま全体**が見える。ただし約90pxと小さい |
| 本体の画面 | **横長に切り取られる**（比1.72）。高さの42%が失われる |

画面では上から **10%〜69%** の帯だけが映る。
さらにその下半分にはタイトルの帯が重なって暗くなる。

```
  正方形の絵（1000×1000 とした場合）
  ┌──────────────────┐  0%
  │   切られる         │
  ├──────────────────┤ 10%
  │                    │
  │   ★ ここに主役     │   ← 安全地帯（10%〜45%）
  │                    │
  ├──────────────────┤ 45%
  │   タイトルの帯が    │
  │   重なって暗くなる  │
  ├──────────────────┤ 69%
  │   切られる         │
  └──────────────────┘ 100%
```

- **主役（キャラクター・盤面・タイトルになる要素）は上から10〜45%へ置く**
- 下の3割は本体の画面では見えない。**背景や余韻に使う**
  （カセットとして見るときには映るので、無意味ではない）
- 左右は切られないので、横方向は端まで使ってよい

### 指示文へ足す一文

```
・画面の下から3割には、重要な要素を置かないでください。
　主役は上寄り（上から1割〜4割半の範囲）に配置してください。
```

## 発注の大原則

### 原則1: 機能する部品はAIに描かせない

画面・PLAYボタン・点灯は**すべてCSSで上から描く。**
AIには「そこに何も置いていない平らな面」だけ確保してもらう。
生成AIは座標を指定どおりに描けないので、**描かせなければズレようがない。**

### 原則2: 差込口は描いてよい

カセットは本体の**裏へ潜り込ませて消す**ので、絵の差込口と1ピクセル単位で
合わせる必要が無い。**ここは作り込んでもらってよい**（前回「穴が開いてるだけ」
になっていた部分）。

### 原則3: 文字は一切描かせない

タイトルはHTML側で描く。生成画像の文字は毎回崩れる。

### 原則4: 光らせない

**これが今回いちばん重要。** 本体はスケルトンで内部の基板が見えるが、
**発光は一切させない。** 挿さったゲームの色をCSSで乗せて光らせるため、
最初から光っていると色が混ざって濁る。

内部は**暗めのグレー**で描いてもらう。暗い面ほど、上から乗せる光がよく乗る。

### 原則5: 位置は「だいたい」でよい

ズレはCSS変数を詰めれば吸収できる。求めるのは下の「絶対条件」だけ。

## 実機本体 `console-body.png`（1600 × 760）

現実には存在しない、**スケルトンの横長携帯機**。
ゲームボーイアドバンスの骨格に、近未来的な質感を足したもの。

配置はGBA準拠。**十字キー左・画面中央・A/Bボタン右・上端に差込口。**

### 絶対条件（外れたら作り直し。後から直せない）

1. **背景が完全に透過している**
   → 本体の形をそのまま切り抜きに使うので、これが崩れると成立しない
2. **文字・数字・ロゴが1つも無い**
3. **どこも発光していない**（内部の基板もLEDも、すべて消灯）
4. **画面の場所が平らな暗いくぼみ**で、中に何も描かれていない
   → 中央、幅は本体の3割強、高さは6割強
5. **画面の下に、平らな空き地がある**
   → 横長。ここへPLAYボタンを重ねる。ボタンも文字も描かない
6. **本体が画像の枠内に収まっている**（見切れていない）
7. **色が無彩色**（グレー〜黒）。特定の色に寄せない

### 描き込んでほしいところ

- **上端中央の差込口**（カセットの差し込み口）。ここは作り込んでよい
- **十字キー**（左側）、**A/Bボタン**（右側）、**スピーカー**（右下）
- **透けた樹脂ごしに見える内部**。基板、配線、チップ、ネジ、ケーブル
  → スケルトンなので、中身が見えているほど良い

### 指示文（そのまま貼れる）

```
架空の携帯ゲーム機を正面から描いてください。1600×760ピクセル、背景は完全透過のPNG。

全体:
・横長の携帯ゲーム機。ゲームボーイアドバンスのような骨格
・筐体はスケルトン（半透明の樹脂）で、中の基板・配線・チップ・ネジが透けて見える
・本体全体が画像の中に収まること。見切れさせない

配置:
・中央に画面（左右の中央、やや上寄り）
・画面の左に十字キー
・画面の右にA・Bボタン
・右下にスピーカーの穴
・上端の中央にカセットの差し込み口（横長のスリット）。ここは作り込んでよい

必ず空けておく場所（ここに何も置かないでください）:
・画面の部分は、平らで暗いくぼみにする。中に映像も模様も一切描かない
・画面のすぐ下に、横長の平らな空き地を作る。
　ボタンも文字も模様も置かない

質感と色:
・グレーから黒の無彩色のみ。青や緑などの色に寄せないこと
・半透明の樹脂と、内部の基板の質感

絶対に守る条件:
・どこも発光させない。基板もLEDもランプも、すべて消灯した状態で描く
・内部の基板は暗めのグレーで描く
・文字、数字、ロゴ、メーカー名を一切描かない
・背景は完全透過。影は本体の真下にごく薄くだけ

写実的な3DCG風。
```

### 受け取り時の確認

- [ ] 背景が透過になっているか（白や黒の板が付いていないか）
- [ ] どこにも文字が入っていないか
- [ ] **どこも光っていないか**（ここが一番よく外れる）
- [ ] 内部の基板が透けて見えているか
- [ ] 画面の場所が平らな暗いくぼみで、中が空か
- [ ] 画面の下に平らな空き地があるか
- [ ] 色が無彩色か（青や緑に寄っていないか）
- [ ] 本体が見切れていないか

寸法の基準図を `docs/reference/console-layout.svg` に置いた。
**赤い枠が「何も置かない空き地」、青い枠が「描き込んでよい場所」。**
生成AIに渡すときは、ブラウザで開いてスクリーンショットを撮って添付する。

## いま試作が使っている数値

絵を受け取ったら、この値を測り直して入れる。**絵を描き直させる必要は無い。**

```css
.deck{
  aspect-ratio:1600/760;
  --screen-x:33%; --screen-y:13%; --screen-w:34%; --screen-h:63%;  /* 画面 */
  --slot-x:50%;                                                    /* 差込口の中心 */
  --play-x:38%; --play-y:80%; --play-w:24%; --play-h:14%;          /* PLAY */
}
```

カセットは本体幅の **22%**（GBA実機の比率に合わせた）。

## 画面の作り

```
   ┌────┐ ┌────┐ ┌────┐ ┌────┐
   │HELL│ │BOSS│ │HEXA│ │ ?  │   ← カセット置き場（中で絵が光っている）
   └────┘ └────┘ └────┘ └────┘
                │ 選んだものが上から降りてくる
                ▼
      ╔═══════════════════════╗
      ║      ▁▁▁▁▁▁▁          ║  ← 差込口。カセットは裏へ潜って消える
      ║  ✛   ┌───────┐   ● ●  ║
      ║      │ 絵    │        ║  ← 画面（CSS）
      ║      └───────┘        ║
      ║       ( PLAY )        ║  ← PLAY（CSS）
      ╚═══════════════════════╝
```

1. カセットを押すと、上から降りて本体の**裏へ潜り込み、完全に消える**
2. 潜り切った瞬間、**差込口が一度だけ強く光る**（データが渡ったことを見せる）
3. **内部の基板がそのゲームの色に灯り**、画面に絵が出る
4. PLAYでゲームへ移動する

カセットは中で絵が光っている状態にしてある。挿すとその光が本体へ移るので、
**光の出どころが1本につながる**。「挿した」より「流し込んだ」に見せたい。

### 実装で守ること（試作で対応済み）

- カセットは `<button>`、PLAYは `<a>`。**キーボードだけでも辿れる**
- 「動きを減らす」設定では演出を飛ばす
- 携帯ではPLAYを本体の下へ出して全幅にする（本体が小さいと押しにくいため）
- COMING SOONは押しても挿さらず、いま挿さっているゲームも外さない
- 取り出したカセットは置き場に空のくぼみとして残す（列に穴が空かないように）

### 内部を光らせる仕組み（画像を受け取ってから組む）

本体の絵は不透明で構わない。**色は上から乗せる。**

- 本体のPNGの**アルファをマスクに使う**ので、背景の透過が絶対条件になる
- 色付きの光を `mix-blend-mode: screen` で重ねると、
  暗い部分だけが色を拾って「内部が光っている」ように見える
- だから内部は**暗めのグレー**で、**消灯した状態**で描いてもらう必要がある

## 新作を1本足すときの手順

差し替えは済んでいるので、これが今後の定型作業になる。
**用意するのは絵1枚だけ。** 残りはコードを数行足すだけで終わる。

1. **絵を1枚作る**（1000×1000 前後の正方形・文字なし）
   → 上の「安全地帯」を守ること。下の3割は本体の画面で切れる
2. 原本を `images/portal/source/cart-label-<ゲーム名>.png` へ置く
3. `tools/portal-images.mjs` の `TARGETS` へ1行足して変換

   ```
   { src:'cart-label-<ゲーム名>.png', out:'cart-label-<ゲーム名>.webp', width:640, note:'ラベル' }
   ```

   ```
   npm run portal:images
   ```

4. `index.html` の `GAMES` へ1件足す（COMING SOON の**手前**へ）

   ```js
   { id:'xxx', name:'ゲーム名', desc:'一行説明', href:'games/xxx.html',
     color:'#rrggbb', art:'images/portal/cart-label-xxx.webp',
     tags:['ランキング','スマホ対応'] },
   ```

   `color` はそのゲームの色。カセットの発光、本体の内部発光、PLAYの枠が
   この1色から決まる。**他に色を書く場所は無い。**

5. `NOW PLAYING` の本数と `LAST UPDATE` を直す
6. パッチノートに追記する
7. ランキングがあるなら `tools/ranking-to-discord.mjs` の `GAMES` にも足す
8. `npm run verify` と `npm run test:portal` を通す

### 確認済みのこと

- **10本並べても1段のまま。** カセット置き場は折り返さず横へ流れる。
  1280/900/599/390px のいずれでも1段で、ページ自体は横に伸びない
- **PCはドラッグでも動かせる。** 掴んで動かしただけではゲームは挿し変わらない
  （8pxを超えて動いたらクリックを無効にする）
- あふれている間だけ左右の矢印を出す。携帯では矢印を出さず、指のスクロールに任せる
- COMING SOON は常に最後に置く。押しても挿さらず、遊べるゲームも外さない

**折り返さない理由。** 折り返すと本体との距離が作品数で変わり、
10本並んだときに置き場が縦へ伸びて本体が画面外へ押し出される。

## 生成AIがよく外すところ

指示しても高確率で無視される。**毎回目視で確認する。**

| 外れること | どうなるか |
|---|---|
| 背景の透過 | 板が付いてきて、切り抜きもマスクも成立しない |
| 「光らせない」 | 内部を光らせてきて、CSSで乗せる色と混ざって濁る |
| 「文字を描かない」 | 勝手にメーカー名やロゴを入れてくる |
| 「空き地を作る」 | 画面に映像を描いてしまい、絵を出す場所が無くなる |
| 「無彩色」 | 青や緑の樹脂にしてきて、ゲームごとの色が乗らない |

サイズが違っても**縦横比（1600:760）だけは守らせる。**
