# HELL RUNNER 一時停止機能 実装指示書

作成日: 2026-08-16  
状態: **実装前。別AIへ委託するための確定仕様**

## 1. 目的

プレイ中にゲーム全体を安全に止め、同じ地点から再開できる一時停止機能を追加する。

「一時停止」と「音だけ停止」は別機能として扱う。HUDの入口は音符・スピーカーではなく、意味が明確な `Ⅱ` 一時停止アイコンにする。

## 2. 確定UI

### プレイ中

- HUD直下の右上へ、小さな黒鉄＋赤縁の `Ⅱ` ボタンを置く
- Canvasの重要表示を隠しにくい位置にし、PC・携帯ともゲーム枠内からはみ出させない
- 見た目が小さくても、押せる範囲は最低48×48pxを確保する
- `aria-label="一時停止"` を付ける
- タイトル画面、能力選択、ゲームオーバー画面では非表示

### 一時停止画面

ゲーム画面を暗く覆う既存 `.overlay` 系の見た目に合わせ、中央へ以下を表示する。

1. `PAUSED`
2. **PLAY（再開）**
3. **サウンド ON/OFF**
4. **HELL RUNNER TOP**

重要:

- 「ゲーム置き場へ戻る」は置かない
- `HELL RUNNER TOP` はポータルではなく、このゲームのタイトル画面へ戻す
- 再開ボタンは既存PLAYボタンの画像・枠・CSSを流用してよい
- 見た目を流用しても、再開時に `startGame()` を呼んではいけない。ゲームを初期化せず、停止地点から戻す専用処理にする
- `HELL RUNNER TOP` はゲームオーバー画面にある既存HOMEボタンの画像・枠・CSSをそのまま流用する。新しいTOPボタン素材は作らない
- PLAYを押しても即座に走り出さず、転生発動時と同様の3秒カウントダウンを経て再開する

## 3. 操作

- 画面の `Ⅱ` ボタン: 一時停止
- 一時停止画面のPLAY: 3秒カウントダウンを開始し、終了後に再開
- PCの `Escape` または `P`: 一時停止／再開
- ブラウザのタブ切替、アプリ切替、画面ロックなどで `document.hidden === true` になった場合は自動で一時停止
- 画面へ戻っても自動再開しない。必ず本人がPLAYを押す
- 一時停止ボタンのタップをジャンプ入力として扱わない

## 4. 停止するもの

一時停止中は次の進行をすべて止める。

- プレイヤー移動、重力、ジャンプ、滑空
- 距離、スコア、速度上昇
- 地形生成、敵・ライバル・死神
- コイン、能力、復活判定
- パーティクル、コウモリなどの時間更新
- BGM再生とクロスフェード更新
- ゲーム内タイマー、通知タイマー

描画は継続してよいが、ゲーム状態は更新しない。一時停止直前の場面を背面に静止表示する。

## 5. 状態管理

- 既存 `state` に `paused` を追加する方針でよい
- 一時停止へ入れるのは原則 `state === 'playing'` のときだけ
- 一時停止直前の状態を保持し、PLAYで専用の `pauseCountdown` へ移行する。3秒経過後に `playing` へ戻す
- 一時停止時に `holdingInput = false`、`jumpQueued = false` とし、再開直後の意図しないジャンプを防ぐ
- `pauseCountdown` 中も `holdingInput = false`、`jumpQueued = false` を維持し、画面タップ・Space・↑・Wをジャンプとして受け付けない
- `loop()` / `update()` は `paused` と `pauseCountdown` 中にプレイヤー・地形・距離などのゲーム更新を行わない。カウントダウン用タイマーだけを進める
- `draw()` の距離判定では `paused` と `pauseCountdown` をプレイ中と同じ現在距離として扱う。現在の背景が0mへ戻って見えないよう注意する
- 一時停止時間を次フレームの巨大な `dt` として加算しない。再開時にフレーム時刻をリセットする
- `goHome()`、`startGame()`、`endGame()` の各経路で一時停止Overlayが残らないよう必ず閉じる

### 再開カウントダウン

- 転生時の `reviveCountdown` と同じ見せ方・文字サイズ・中央配置を流用する
- 表示は `3` → `2` → `1` → `START!`。既存のカウント表記が異なる場合は既存へ揃える
- カウント中は一時停止メニューを隠すが、背面のゲームは静止したままにする
- BGMはPLAYを押してカウントダウンへ入った時点で停止位置から再開し、再開の予告として使う
- サウンドOFFの場合は再生しない
- カウント完了時にもう一度 `holdingInput` と `jumpQueued` をクリアしてから `state = 'playing'` にする
- カウント中にタブ・アプリを離れた場合は再び `paused` へ戻し、復帰後にPLAYを押したら3秒を最初からやり直す

## 6. BGMとサウンド

### BGM

- 一時停止では全 `bgmAudios` を `pause()` するが、`currentTime` は0へ戻さない
- 既存 `stopBGM()` は時刻を0へ戻すため、一時停止処理へ流用しない
- 例として `pauseBGMForGamePause()` と `resumeBGMFromGamePause()` を分ける
- PLAYで3秒カウントダウンへ入った時点で、現在距離の曲とクロスフェード比率を復元し、停止位置から再生する
- `HELL RUNNER TOP` へ戻る場合は完全終了なので、既存 `stopBGM()` で0へ戻してよい

### サウンド ON/OFF

- 一時停止メニュー内だけに置く。HUDへ別の音符ボタンは増やさない
- BGMだけでなく、ジャンプ・コイン・ライバル・悲鳴などゲーム音全体を対象にする
- 表示は現在状態が分かる `サウンド ON` / `サウンド OFF` とする
- OFF状態は `localStorage` へ保存し、次回起動時にも維持する
- OFFでもゲーム進行は止めない
- iPhone Safari用のWeb Audio経路を壊さないこと

## 7. TOPへ戻る処理

一時停止画面の `HELL RUNNER TOP` は次を行う。

- 一時停止Overlayを閉じる
- BGMを完全停止して再生位置を0へ戻す
- `state = 'idle'`
- HUDと一時停止ボタンを隠す
- タイトル画面 `startScreen` を表示する
- ゲーム置き場 `../index.html` へは遷移しない
- 記録・能力解放・ベストスコアを消さない

ボタンの見た目はゲームオーバー画面の既存HOMEボタンを必ず流用する。処理も既存 `goHome()` を安全に共用できるなら拡張してよいが、ゲームオーバー画面からの既存HOME動作を壊さないこと。

## 8. 見た目とレスポンシブ

- 既存の地獄・黒鉄・赤金色のUIへ合わせる
- 新しい画像生成は不要。既存ボタン素材とCSSを優先する
- 390×844の携帯表示で横スクロールを出さない
- iPhoneのノッチやブラウザUIを考慮し、右端・上端へ密着させすぎない
- 一時停止Overlayは縦に収まらない端末でスクロール可能にする
- `prefers-reduced-motion` では新しい点滅・反射アニメーションを止める

## 9. 実装上の注意

- `games/temple-run-clone.html` はbase64埋め込みで約6.5MBある。全体読込・全体書換え・フォーマッタは禁止
- 500文字超の埋め込み行を避け、目的箇所だけ部分編集する
- コメントは日本語で「なぜ必要か」を記録する
- 単一HTML、`file://` 直接起動可能という既存条件を維持する

## 12. 実装アンカー（2026-08-16 コード実測）

実装前に既存コードを確認した結果。**推測せず、ここに書かれた事実に従うこと。**
行番号は編集で動くため、必ず `grep -n` で現在位置を取り直す。

### 12.1 `reviveCountdown` は変数ではなく `state` の値

指示書5節が参照している転生カウントダウンは、すでに `state` の一値として実装されている。
`pauseCountdown` は**まったく同じ形**で作れる。`loop()` 内のこのブロックがひな形:

```js
} else if(state === 'reviveCountdown'){
  reviveTimer -= dt;
  ...
  if(reviveTimer <= 0){
    state = 'playing';
  }
}
```

`state = 'reviveCountdown'` の設定箇所と、`draw()` 側の `if(state === 'reviveCountdown')`
による表示処理をそれぞれ確認し、同じ構造で `pauseCountdown` と `pauseTimer` を足す。

### 12.2 巨大 `dt` 対策は既に入っている

```js
const dt = Math.min(0.033, (now-lastTime)/1000);
```

**`dt` は33msで頭打ちになっている。** タブ復帰時に巨大な `dt` が入る事故は既に防がれている。
指示書5節の「フレーム時刻をリセットする」は、この防御を知らずに書いたもの。
`lastTime` の明示リセットを足しても害は無いが、**これを理由に新しい時刻管理の仕組みを
作らないこと**。既存の1行で足りている。

### 12.3 既存の停止フラグ `debugFrozen` と衝突させない

デバッグ用の停止フラグが既にある。

```js
if(state === 'playing' && !debugFrozen){
  update(dt);
}
```

一時停止は `debugFrozen` を流用せず、**`state` で表現する**。デバッグで凍結中に
一時停止した場合や、その逆でも壊れないようにする。`debugFrozen` の既存挙動は変更しない。

### 12.4 パーティクルとコウモリは現在「常に動く」。ここが指示書と矛盾する

`loop()` の以下2行は `state` を見ずに毎フレーム実行されている。

```js
updateBats(dt);       // タイトル画面でもコウモリは飛ばしておく
updateParticles(dt);  // カウントダウン中も粒子は動かし続ける
```

コメントのとおり、**転生カウントダウン中に粒子を動かし続けるのは意図的な既存仕様**。
一方で本指示書は4節で「パーティクル、コウモリなどの時間更新」を止めると定め、
5節では「カウント中も背面のゲームは静止したまま」としている。**両立しない。**

この指示書の指定を優先する。すなわち:

- `paused` 中: `updateBats` / `updateParticles` を止め、`animT` も進めない
- `pauseCountdown` 中: 同じく静止させる（転生カウントダウンとは挙動が異なってよい）
- `reviveCountdown` の既存挙動は**変更しない**。粒子は今まで通り動かす

`animT` は現在 `if(!debugFrozen) animT += dt;` で進んでいる。背面を完全に静止させるには
この条件へ `paused` と `pauseCountdown` を加える必要がある。**ここを忘れると、
止めたつもりでもコウモリと幽霊だけが動き続ける。**

### 12.5 流用するボタンのid（実在確認済み）

| 用途 | id | 置き場所 |
|---|---|---|
| ゲームオーバーのHOME（`HELL RUNNER TOP` の流用元） | `homeBtn` | ゲームオーバー画面 |
| リトライ | `retryBtn` | ゲームオーバー画面 |
| タイトルのSTART | `startBtn` | タイトル画面 |
| 能力選択のSTART | `abilityStartBtn` | 能力選択画面 |
| タイトル画面そのもの | `startScreen` | — |

**`backToHubBtn` は別物**。これはゲーム置き場へ戻るボタンで、一時停止メニューには置かない
（指示書2節の「ゲーム置き場へ戻るは置かない」はこれのこと）。

### 12.6 未実装のため新規追加になるもの

| 指示書の要求 | 現状 |
|---|---|
| `visibilitychange` による自動一時停止 | **ハンドラは既に存在する（13.3参照）。新規追加ではなく拡張すること** |
| `prefers-reduced-motion` 対応（8節） | このゲームには未使用。`index.html` にはある |

`prefers-reduced-motion` は、**新しい点滅・反射アニメーションを追加しないなら対応不要**。

### 12.7 テスト時の注意: エラーが握り潰される

`loop()` 全体が `try/catch` で囲まれており、例外は `console.error('game loop error:', err)`
を出すだけでループが継続する。**画面上は動いて見えるのに内部で例外が出続ける状態が起こりうる。**

Playwrightのテストでは、`page.on('console')` で `game loop error` を拾い、
**1件でも出たら失敗**とする検証を必ず入れること。

## 13. 再検証（2026-08-16 大小ジャンプ実装後）

12章のレビューは**大小ジャンプの実装前**に行ったもの。その後、入力まわりの作りが
変わったため差分を再検証した。**5節と6節の記述は、以下で上書きすること。**

### 13.1 `holdingInput` へ直接代入してはいけない

5節に「一時停止時に `holdingInput = false`、`jumpQueued = false` とし」とあるが、
**現在の `holdingInput` は導出値**であり、直接書いても保たれない。

```js
function syncHoldingInput(){
  holdingInput = activeJumpPointerId !== null || keyboardJumpHeld;
}
```

`holdingInput = false` と代入しても、次に何かのポインタ操作が起きた時点で
`syncHoldingInput()` が走り、`activeJumpPointerId` が残っていれば**true へ戻る**。

**入力解除には必ず既存の `clearJumpInput()` を呼ぶこと。**

```js
function clearJumpInput(){
  activeJumpPointerId = null;
  keyboardJumpHeld = false;
  holdingInput = false;
  jumpQueued = false;
}
```

指示書6節が求めていた「入力解除処理を関数化する」は**すでに実現済み**。
新しい解除処理を書かず、これを使う。

### 13.2 【重要】一時停止時は `jumpCanBeCut = false` も必要

これを忘れると、**上昇中に一時停止したプレイヤーの大ジャンプが、再開時に勝手に
小ジャンプへ変わる。** 奈落の上なら死につながる。

理屈は次のとおり。大小ジャンプのカット判定は毎フレームの状態で行う。

```js
if(jumpCanBeCut && player.vy < 0 && !holdingInput){
  player.vy *= JUMP_RELEASE_CUT;
  jumpCanBeCut = false;
}
```

一時停止で `clearJumpInput()` を呼ぶと `holdingInput` が false になる。
上昇中（`player.vy < 0`）に停止した場合、`jumpCanBeCut` は true のまま残るため、
**再開した最初のフレームでカット条件が成立してしまう**。
プレイヤーは指を離していないのに、跳躍が切られる。

一時停止へ入る処理で、入力解除と一緒に必ず落とすこと。

```js
clearJumpInput();
jumpCanBeCut = false;  // 停止中に指を離した扱いになり、再開時へカットが持ち越されるのを防ぐ
```

**空中で停止した場合、再開後は停止前の軌道をそのまま続ける**のが正しい挙動。

### 13.3 `visibilitychange` は既に存在する。二重登録しない

12.6で「ハンドラが1つも無い」と書いたが、大小ジャンプ実装時に追加された。

```js
document.addEventListener('visibilitychange',()=>{ if(document.hidden) clearJumpInput(); });
```

現状は**入力解除だけ**で、一時停止はしない。3節が求める自動一時停止は、
**このハンドラを拡張して実現すること。** 同じイベントへ別のリスナーを足すと、
解除と停止の順序が読みづらくなる。

拡張後も「復帰時に自動再開しない」（3節）を守る。

### 13.4 更新された実装アンカー

| 項目 | 現在の実測 |
|---|---|
| 入力解除 | `clearJumpInput()`（`activeJumpPointerId` / `keyboardJumpHeld` / `holdingInput` / `jumpQueued` を一括で落とす） |
| `holdingInput` | 導出値。`syncHoldingInput()` 経由でのみ更新される |
| 携帯の押下元 | 最初の `pointerId` だけを採用。2本目の指を離しても解除されない |
| カット権 | `jumpCanBeCut`。`startGame` / `goHome` / 死亡 / 転生 の各所で false に落としている |
| `visibilitychange` | 実装済み。`document.hidden` で `clearJumpInput()` を呼ぶ |
| デバッグパネル | `JUMP HEIGHT` セクションが増えた。一時停止ボタンの配置が重ならないか確認する |

### 13.5 テストへの追加

12章の必須テストに加えて、以下を確認する。

1. **上昇中に一時停止し、再開しても跳躍が小さくならない**
   （`jumpCanBeCut` の持ち越しが起きていないこと。13.2の担保）
2. 一時停止後に画面をタップしても `holdingInput` が復活しない
   （`clearJumpInput()` を使っていれば通る。直接代入だと失敗する）
3. 空中で一時停止し、再開後に停止前と同じ軌道で着地する
