## 1. この画面で作りたいもの

仮称 **NEON GATE LINEUP（ネオンゲート式）**。

雨のネオン街に立つ、7本の縦長キャラクターゲートから挑戦者を選ぶ画面。添付した完成イメージのように、選択中の1人だけが**幅・明るさ・前面Depth**を上げてせり出し、他の6人は暗く沈む。上部は大きい金属金の`TODAY'S CHAMPION / REMASTER`ロゴと、黒鉄の配管・端末フレームで世界観を作る。

目標は、携帯で開いた瞬間に「これはちゃんとした対戦ゲームのキャラセレクトだ」と感じられること。PCはその横展開であり、**最初に優先するのは縦持ちスマホの見栄えと押しやすさ**。

### 絶対に避けること

- 現在のようなPC向け一覧を縮小しただけのグリッド
- 横長に引き伸ばされたキャラ画像
- キャラ名・肩書き・枠・背景が重なって読めない構成
- 画像生成時の意味不明な文字をそのままUIへ使うこと
- 選択中キャラとは別に、大型モニター／主役カードを上部へ置く構成
- 小さすぎて携帯で直接押せないキャラカード

## 2. 実装上の前提（素材づくりで守ること）

### 2.1 選択演出はPhaserで完結させる

選択状態を示す装飾を背景上へCSS／DOM座標で重ねない。選択中ゲートの枠・発光・せり出しはすべてPhaserの同じ座標系で描く。

- 選択変更時だけ、選択キャラの固有色がゲート枠・背景の雨粒・小さな光へ短く走る
- 連打で何度も演出をリセットしない。選択が変わった時だけ再生する
- 選択ボイスがない／読み込み中でも、光の演出で画面が静止して見えない状態を避ける

### 2.2 文字は画像に焼き込まない

キャラ名、肩書き、番号、`START DUEL`、操作説明、画面タイトルはコードで表示する。素材内に必要なのは装飾だけ。

理由:

- 日本語・英語表記を後から直せる
- 端末ごとに文字が潰れない
- 画像生成の誤字を持ち込まない
- アクセシビリティと操作説明を保てる

### 2.3 タップ判定は画像の見た目とは別に確保する

スマホでは、見えている細いゲート画像だけを押す仕様にしない。各キャラは最低でもおおむね **44px × 44px以上** のタップ判定を持つ。

画面上は7本の縦ゲートが並んで見えてよいが、実際の操作は次を満たす。

- カードをタップして選択
- 左右スワイプでも選択変更
- 選択中のカードをもう一度押しても、ボイス・選択演出を最初から再生しない
- PCではクリックに加え、左右キーでも選択できるようにする
- STARTボタンは画面下部に固定し、カード操作と重ならない

## 3. 素材一覧（制作するもの）

### A. 選択画面専用背景 — 2枚

| ファイル名 | 用途 | 原画の目安 | 配信用の目安 |
| --- | --- | ---: | ---: |
| `select-bg-mobile` | 縦持ち携帯 | 2160 × 3840px | WebP、1440 × 2560px前後 |
| `select-bg-desktop` | PC・横長 | 3840 × 2160px | WebP、1920 × 1080px前後 |

内容:

- 雨の夜の日本風ネオン都市
- 濡れた路面の反射、都市建築の輪郭、遠景の看板、薄い霧
- 上部に大きい`TODAY'S CHAMPION / REMASTER`ロゴと黒鉄フレームを置ける暗く読みやすい空間
- 下部にSTARTボタンを置くため、細かすぎる看板・人物・強い光を避ける
- キャラゲートの背後は暗めにして、カードの発光が主役になるようにする
- 背景の中央に大きな人物、読める文章、既存キャラに似た顔を描かない

背景は「カードを置く舞台」。カード用のキャラ絵と競合しないことを最優先する。

### B. 選択演出用の追加画像 — 現時点では不要

選択時の発光、カード枠、雨粒の反射はPhaserの図形・パーティクルで実装する。状態別のランプ画像・丸いステータス表示・位置合わせが必要な別画像は作らない。

### C. ネオンゲート用・縦長キャラアート — **14枚**（最重要）

各キャラに「通常ゲート」と「選択中の主役ゲート」の**2種類**を作る。添付イメージのように選択中だけ中央で一段太く・明るくなり、通常状態の細い6本とは別の構図が必要になるため、同一画像の単純拡大では済ませない。

14枚すべてで絵柄、遠近感、照明、足元の反射線を揃える。各キャラを別々の世界で描いた感じにせず、同じ都市・同じ対戦ゲームのロスターに見せる。

共通仕様:

- 画角は縦長。通常ゲートは**幅:高さ = 1:5.5〜1:6.5**、選択中ゲートは**幅:高さ = 1:3.6〜1:4.4**
- 原画: 通常`900 × 5400px`前後／選択中`1400 × 5400px`前後。配信用はWebPで、通常幅600〜720px・選択中幅900〜1100pxを目安
- キャラは頭から足先まで入れる。足元は切らない
- 背景込みの完成絵。ただし**共通ゲート枠は描かない**。枠はEの透過フレーム素材を上へ重ねるため、カードの外枠、名前、肩書き、番号、文字、ロゴを入れない
- キャラの頭頂と足元に約5〜8%の余白を残す。実装で拡大しても頭・靴が切れないようにする
- キャラの顔・胸・武器がカード中央寄りに来る構図。横端へ重要な部位を逃がさない
- 光源は正面または斜め前から。通常ゲートを暗転させても輪郭が残り、選択中は同じ光源を強めても不自然にならないようにする
- 色はキャラ固有色を強く出すが、背景の明度はキャラより抑える
- 画面内に読める文字、英単語、数字、ロゴ、透かしを入れない
- 既存のバトル用透過モーション素材とは別物。戦闘ポーズを流用しない

#### キャラごとの構図メモ

**RAVEN**

- 刀を低く構え、こちらを静かに見据える
- 余計なポーズで暴れず、クールで厨二的な危険さを優先

**MIKA**

- 明るく挑発的。ピンクの勢いはあるが、可愛いだけではなく対戦者として強そうに見せる
- 足元の反射やローラーを見せる

**BRICK**

- 身体の大きさと鉄拳の重量が即座に分かる
- ポスター内で小さく見えないよう、肩・腕・胴を太く明確にする

**NOISE**

- 音楽キャラだと分かるが、DJの立ち絵で止めず、対戦者としての圧を出す
- 紫の音波は背景演出として扱い、輪郭を食わないこと

**KIRI**

- 落ち着いた大人のイケメン。中性的・少年寄りにしすぎない
- 白紫の霧や通信波のモチーフを静かに入れる

**VIVI**

- 大人の美形ではなく、年齢を固定しない「整いすぎた美少年」
- 白い天使性と黒い悪魔性が一つの身体で不安定に混在する
- 叫んだ時の狂気を想像できる顔。ただし最初から絶叫顔にはしない
- 壊れた光輪、白黒の羽根、氷青と赤紫の異物感を入れる
- 白主体でも背景に埋もれないよう、黒側と輪郭光で形を保つ

**TΩ9**

- 信楽焼の狸をモチーフにした、リアルすぎないぽっちゃり体型のゲームキャラ
- 赤いちゃんちゃんこ、笠、赤く染まった頬。左手に徳利、右手に通い帳を必ず持つ
- 徳利で酒を飲んでから酔拳へ入る。単なるオーガ・ロボット・キメラにしない
- 赤を主役にしつつ、狸の茶色と笠の黒で読み分ける

### D. キャラ紋章 — 7枚（推奨）

ゲート上部や、選択中キャラの情報部に使う小さなマーク。名前が読めなくても誰を選んでいるか補助できる。

- 512 × 512pxの透過PNGまたは透過WebP
- 1色または2色まで。小さくしても判別できる太い形
- 文字・イニシャルは不要

| ID | 紋章の方向性 |
| --- | --- |
| RAVEN | 割れた刀身／鳥の翼を思わせる刃 |
| MIKA | ローラーの車輪＋稲妻 |
| BRICK | 鉄拳／六角ボルト |
| NOISE | 波形／砕けたスピーカー |
| KIRI | 霧の波紋／細い剣閃 |
| VIVI | 割れた光輪＋二対の羽根 |
| TΩ9 | 笠、徳利、通い帳、酔拳の軌跡 |

### E. 共通ゲート枠 — **2枚（先に制作・必須）**

カセットと同じ方式にする。黒鉄の質感・細い配線・傷・金の縁はPhaser図形へ任せず、**共通の透過フレーム画像**として先に作る。7人分の枠を個別に描かない。

| ファイル名 | 外寸（原画） | 透明の内寸（原画） | 用途 |
| --- | ---: | ---: | --- |
| `gate-frame-lineup` | 900 × 5400px | 700 × 4740px | 通常6人用の黒鉄フレーム。内側は完全透明 |
| `gate-frame-selected` | 1400 × 5400px | 1140 × 4740px | 選択中1人用の白金／鈍金フレーム。内側は完全透明 |

- 内寸は外寸の中心へ固定し、通常・選択中のキャラアートも**それぞれこの内寸と同じ縦横比**で制作する。Phaserではキャラアートを先、フレームを後ろではなく**前面**へ同一座標・同一倍率で重ねる
- フレームの内側は透明PNG／alpha対応WebPとし、透明域に背景色やチェッカー模様を焼かない。四隅と内寸中央のalpha=0を検査してから採用する
- 選択中の発光・暗転・せり出しはPhaserで加えるが、金属の基本質感と立体的な縁はこの画像で担保する
- フレーム画像にキャラ、読める文字、番号、ロゴを入れない。キャラの固有色はPhaserの光とCのキャラアートで出す

任意で`ui-metal-plate`をSTARTボタン用に追加できる。ただし文字は入れない。

### F. 選択時の短い装飾VFX — 3枚程度（任意）

静止画だけで十分に完成させてから追加する。実装時の優先度は低い。

- `select-scanline`：選択カードを走る細い走査光
- `select-shards`：VIVIやTΩ9にも使える小さな破片・火花
- `select-rain-glint`：濡れた地面の反射が一瞬強くなる光

全キャラ共通で使える抽象素材にし、キャラごとの専用VFXは作らない。キャラ固有の派手さは戦闘中の攻撃エフェクトへ残す。

## 5. 画面構成・安全領域

### 縦持ち携帯（最優先）

1. 上部 0〜22%: 大きい`TODAY'S CHAMPION / REMASTER`ロゴ、選択中キャラの番号・名前だけ
2. 中央 18〜78%: 7本のネオンゲート。選択中だけ太く、明るく、前へ出る
3. 下部 78〜94%: `START DUEL`ボタン
4. 最下部: スワイプヒント。iPhoneのホームインジケータに重ねない

添付モックどおり、7本は常に同時に見せる。中央に別の大型モニターやカードは作らない。実際のタップ判定は見た目のゲートより広く取り、左右スワイプも併用して操作性を確保する。

### PC

- 同じ素材を横に広げる
- 背景だけはPC専用の横長版を使う
- ゲート・文字・選択演出はPhaser内の同一カメラ座標で拡縮する
- 画像ごとの別CSS位置調整を作らない

### 原画の安全領域

- どのキャラ絵も左右8%、上下5〜8%は重要部位を置かない
- 顔、武器の先端、拳、靴、壊れた光輪は切れやすい端へ寄せない
- UIが重なる可能性のあるカード下15%には、読まれるべき細部を置かない

## 6. 容量・形式・配信ルール

### 原画と配信用は分けて保存する

- 原画: 高解像度PNGを`source/`相当の非公開保管先へ残す
- 配信用: WebPをゲームの`public/assets/`へ置く
- PNG原画をそのままGitHub Pagesへ置かない
- 紋章・VFXなど透明が必須の素材は、alpha対応WebPをまず検討する。背景は不透明WebPでよい

### 初回読み込みの目標

| 区分 | 合計の目安 |
| --- | ---: |
| 背景2枚 | 0.8〜1.2MB |
| 通常ゲート7枚 | 2.1〜3.0MB |
| 選択中ゲート7枚 | 3.0〜4.5MB |
| 紋章・装飾・UI | 0.2〜0.4MB |
| 選択画面の全素材 | **6.1〜9.1MB程度** |

全14枚を最初に同時decodeしない。最初は背景と通常ゲート7枚を読み込み、選択中ゲートはそのキャラを選んだ時にボイス・選択演出の裏で読み込む。残る主役ゲートは操作可能になった後、低優先度で先読みする。これなら初回は3.1〜4.6MB程度に収められる。

さらに大きくなる場合は、次の順で削る。

1. キャラ絵のWebP品質を微調整する
2. 背景の細かいノイズを減らす
3. PC背景を携帯初回ロードから分離する
4. 選択中ゲートのWebP品質を微調整する。通常ゲートの解像度は削りすぎない

画質が必要なキャラゲートを、安易に小さくしすぎない。最初に削るのは背景・装飾側。

### 読み込み順

1. 選択画面の背景（端末に合う1枚）
2. 7人の通常ゲート
3. 現在選択中の主役ゲート1枚
4. 紋章、装飾、残り6人の主役ゲートを低優先度で先読み
5. 選択キャラのボイス・戦闘開始時に必要な戦闘素材

選択中キャラのボイスを鳴らす前に必要な素材だけ読み込み、ボイス終了と戦闘開始演出の間を不自然に止めない。

## 8. 作成順

1. 背景の世界観を決めるため、`select-bg-mobile`のラフと大きいタイトルロゴのコードモックを先に作る
2. RAVEN／VIVIの通常・選択中ゲート4枚を同一テンプレートで先行作成する
3. 携帯で「7本常時表示・選択中だけ太く前へ出る」配置とタップ・スワイプを確認する
4. 残り5人の通常・選択中ゲート10枚を同じ基準で揃える
5. PC背景、紋章、金属装飾を追加し、配信用WebPを最終圧縮する

画像を全部完成させてから初めて画面へ置くのではなく、**背景＋2〜3人の仮ゲート**で早期に操作確認する。これなら、素材を7人分作り直す事故を防げる。
