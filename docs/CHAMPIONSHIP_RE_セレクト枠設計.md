## 第二世代モックからの採用仕様（2026-08-29）

この節が、下記の過去の「選択時も完全に同座標・同寸」という検品規則より優先する。
目的は枠単体の装飾ではなく、7本のゲートが雨の地面へ立つ選択画面として完成させること。

- 7本のゲートは、背景の地面ラインへ足元を正確に合わせて立たせる。背景は最初から
  自然な雨の街と濡れた床として完成させ、キャラごとの色だまり・反射位置を焼き込まない。
  選択中のキャラだけは、Phaserで上下反転した実像反射を短く薄く重ねる。
  反射は足元から下へ急速に消えるグラデーションにし、全身を鮮明な鏡像として見せない。
- 各ゲートは、黒鉄の細く高品位な枠、縦長立ち絵、上部の固有エンブレム、二桁番号、
  キャラ名、別名の順で情報を持つ。長い別名は自動改行・自動縮小を使わず、表示専用の
  一行略称へ置き換える。
- 選択中は、固定の入力領域を保ったまま、同じ列の中でわずかに手前へ出る。選択キャラは
  斜め横向きの通常立ち絵から正面へ向かう選択立ち絵へ切り替え、枠面・足元反射・前方光を
 そのキャラ固有色で連動させる。見た目だけは左右の隣へごく浅く重ねて前面感を出すが、
  隣のエンブレム・番号・顔を隠さず、入力領域は各スロットへ固定する。巨大な背面フレアや
  隣接カードへ漏れる光は使わない。
- 上部には正式タイトル`CHAMPIONSHIP RE // REMASTER`を**透過画像素材**として大きく置く。
  交通信号は不採用であり、再導入しない。
- `START DUEL`もコード描画の矩形ではなく、透過画像素材のCTAとして作成する。ゲート下端から
  CTAまでの余白と、CTAからSafari下部デッドゾーンまでの余白を、実機390px級で同時に検品する。
  デッドゾーンには床、雨、ぼかし反射以外を置かない。
- 枠・選択枠・タイトル・CTAは画像素材で質感を担保する。Phaserは素材配置、入力、選択遷移、
  控えめな前後移動、選択中だけの短い実像反射を担う。

表示専用の別名は以下を初期値とする。

| キャラ | 表示別名 |
| --- | --- |
| RAVEN | ZERO BLADE |
| MIKA | PINK RIOT |
| BRICK | IRON FIST |
| NOISE | BEAT BRKR |
| KIRI | GHOST SIG |
| VIVI | TWO-FACED |
| TΩ9 | DESTROYER |

エンブレムは別名を起点にキャラごとに固有化する。VIVIは`TWO-FACED`を、左右で意匠が異なる
二枚羽の紋章として扱う。発光色は一律の金に固定せず、複数色を持つキャラも含めて各デザインへ
最適な色構成を選ぶ。

## 第二世代の共通レイアウト原図（2026-08-29、素材制作基準）

背景、タイトル、CTA、ゲートを別々の比率で作ってから縮小すると、足元と反射が必ずずれる。
以下を**全素材の唯一の配置基準**とする。Phaserの仮想画面と同じ`941 × 1672`で背景原画を作り、
ゲーム側で非等方拡大しない。

| 要素 | 原画／表示寸法 | 仮想Canvas上の配置 | 算出根拠 |
| --- | --- | --- | --- |
| 背景 | `941 × 1672` | 画面全体 | 背景の1pxをCanvasの1pxへ対応させ、反射位置を座標変換なしで固定する |
| 安全X範囲 | — | `85 ～ 856` | 390×844級の`Scale.ENVELOP`で左右が切れる範囲を除外 |
| ゲート本体 | 原画`450 × 2880` / 表示`100 × 640` | 下端`Y=1170`、中心`Y=850` | モバイルGPUの4096px上限内に原画を収め、タイトル帯とCTAの間へ上部情報・全身立ち絵を収める |
| ゲート中心X | — | `140, 250, 360, 470, 580, 690, 800` | 通常枠は左端`90`、右端`850`。安全範囲の内側へ7枚を10px間隔で置く |
| 選択中の見た目 | `108 × 691`以下 | 同スロット中心、下端`Y=1170` | `1.08`倍で浅く前面へ出しても、端の選択枠は`X=86 ～ 854`に収まる。入力領域は通常枠のまま |
| タイトル | 原画`1440 × 360` / 表示`720 × 180` | 中心`(470, 160)` | 表示範囲`X=110 ～ 830`で、左右見切れを避けながら上部へ大きく置く |
| CTA | 原画`1600 × 400` / 表示`680 × 170` | 中心`(470, 1335)` | 上端`Y=1250`はゲート地面から80px空け、下端`Y=1420`から下は床・雨・反射だけにする |

- 背景は自然な濡れた床だけを描き、キャラごとの位置・色を焼き込まない。ゲートと選択中の
  実像反射だけを共通原図の`X`／`Y`へ置く。左右の見切れを想定した「見た目の画面端」を
  基準に配置してはいけない。
- NORMAL／SELECT枠はこの`100 × 640`へ合わせて**新規制作**する。既存の`98 × 588`・v1〜v6を
  寸法流用しない。各枠の実際の不透明ピクセル下端を`Y=1170`へ合わせてから、背景と合成検品する。
- タイトル、CTAも上表の原画寸法へ作り直す。既存素材は見た目の参考に留め、表示比率や余白を
  完成レイアウトへ無理に合わせない。
- 通常／選択キャラアート、上部エンブレム、番号、名前、別名は、ゲート原画`450 × 2880`の
  共通テンプレートへ合わせて初めて制作する。

## この文書の範囲

キャラ画像はまだ制作・加工しない。NORMAL／SELECT共通の枠と、7枚を置く座標だけを
決めるための初期設計値である。実機Safariの7枚同時検品を通るまで、素材制作へ進まない。

## 現コードから分かった表示条件

- Phaserの仮想画面は `941 × 1672`
- 縦持ちは `Scale.ENVELOP`。余白は出ないが、画面比率が細い端末ではCanvasの左右が切れる
- 実測した `390 × 844` 相当では、見える仮想X範囲は約 `85 ～ 856`。左右約85pxは重要UIを置けない
- 現行の選択処理は、SELECT時に別サイズの枠へ切替えつつカードを拡大している。この仕様では禁止する

## 7枚配置の初期値

| 項目 | 仮想Canvas値 | 理由 |
| --- | ---: | --- |
| 枠の外寸 | `98 × 588` | 1:6。既存の縦長ゲートの比率を保ち、7枚同時でも安全幅に収まる |
| カード間隔 | `10` | 7枚で隣接せず、選択用の外側発光も吸収できる |
| 左端の外枠X | `100` | Safariの見切れ安全域より内側 |
| 各カード中心X | `149, 257, 365, 473, 581, 689, 797` | 外枠幅98と間隔10から算出。全体右端は846 |
| ゲート中心Y（初期検品） | `790` | タイトル下／CTA上の中央領域へ収めるための開始値。実機合成で確定する |
| ゲート外枠の上下 | `496 ～ 1084` | キャラ名・二つ名・操作説明・CTAをSafariデッドゾーンより上へ置ける |

7枚の合計幅は `7 × 98 + 6 × 10 = 746`。安全領域 `85 ～ 856` の中で
左右に余白を残す。SELECTの発光が外へ約9px出ても、左右端が切れない。

## 枠画像の原画規格

NORMALとSELECTは**同一キャンバス・同一内寸**で作る。SELECTで画像を拡大も縮小もしない。

| 項目 | NORMAL | SELECT |
| --- | ---: | ---: |
| 原画外寸 | `900 × 5400` PNG RGBA | `900 × 5400` PNG RGBA |
| ゲーム内外寸 | `98 × 588` | `98 × 588` |
| 透明なキャラ窓 | `756 × 5100` | `756 × 5100` |
| キャラ窓の位置 | X=`72`、Y=`150` | X=`72`、Y=`150` |
| 枠外側 | 四辺alpha=0 | 四辺alpha=0 |

- NORMAL: 暗い黒鉄の細い枠。キャラ固有色の弱い発光をコード側で重ねられる余白を残す
- SELECT: 金主体、同じ外寸・同じ窓位置。金の発光、小装飾、番号インジケーターを枠内に収める
- 中央のキャラ窓は完全透明。キャラ素材・床・背面演出は別レイヤーで置く
- 名前、二つ名、操作説明、番号以外の読ませる文字は枠画像へ焼かない

## SELECT時の実装ルール

1. 7枚のContainer座標は一切変えない
2. NORMALとSELECTは同一 `98 × 588` のまま差し替える
3. Containerの`scale`は常に`1`。選択中だけを拡大しない
4. 選択表現はSELECT枠の金発光、外周の低い粒子、番号インジケーター、文字色で行う
5. 非選択カードは見分けられる明るさを残す。alphaを下げすぎて選択肢を消さない

## タイトルと下部UIの安全設計

- 正式タイトルは添付の`assets/ui/championship-re-title.png`だけを使う。現行の
  `TODAY'S CHAMPION`／自作タイトルは第二完成系へ持ち込まない
- タイトルの透明余白を含む4:1比率は変えない。表示時に非等方スケールしない
- CTAはゲート・キャラ名・操作説明の下、Safari UIデッドゾーンより十分上に置く。
  下部のURL欄に重なり得る範囲は床・雨・反射だけにする
- キャラ名・二つ名・操作説明は枠画像でなくコード側の文字レイヤーで大きく表示する

4. 外寸・内寸・間隔が通ってから、7人共通規格と14枚のキャラ素材へ進む

## v0.2 装飾密度の調整（2026-08-28）

- 第二完成系モックの工業的な密度に寄せるため、NORMALには黒鉄の分割装甲、シアン／マゼンタの配線セグメント、上下の小さな機械的マーカーを追加した。
- SELECTには同一位置の金属装甲、金色のエネルギー節、上下の発光マーカーを追加した。選択時はカードの外寸・位置・透明窓を一切変えずに、光と装甲で主役感を出す。
- NORMAL／SELECTの原画`900×5400`、透明窓`x=72..828 / y=150..5250`、ゲーム内外寸`98×588`は維持する。改めて四隅と透明窓中央のalpha=0を確認済み。

## v2 デザイン方向（2026-08-28、実機確認待ち）

- v0.2は装飾の追加に留まっていたため採用しない。B案の黒鉄ブラケット・分割レールを構造の起点にし、A案の左シアン／右マゼンタの役割分担を統合した`championship-re-frame-*-v2`を新規作成した。
- v2は、四隅の角ブラケット、長い二重レール、5段の装甲節、細い配線、下部の空ソケットを持つ。番号・名前などの文字は焼き込まず、コード側の文字レイヤーで配置する。
- NORMAL／SELECTとも、マスクで透明キャラ窓`x=72..828 / y=150..5250`を完全に打ち抜く。全窓を走査し、非透明ピクセル`0`、四隅alpha=0を確認済み。ゲーム側はv2を参照する。
- 390×844相当の7枚合成まで確認済み。実機Safariで意匠の採否を決めるまで、キャラ縦長アートには進まない。

## v3 B案直結の正式候補（2026-08-28、実機確認待ち）

- v2も不採用。B案の画像を`source/assets/championship-re/references/championship-re-frame-b-master-v1.png`へ基準原画として保存し、`tools/build-championship-re-frame-v3.mjs`で正式比率へ変換する方式へ変更した。
- 変換は、B案を横方向へ引き伸ばさず等方拡大し、中央の単調な直線レールだけを間引く。上下の角ブラケット、左右の黒鉄レール、左シアン／右マゼンタの素材感をそのまま残した`normal-v3`が正本候補である。
- SELECTはB案の同じalpha輪郭から金の後光を作る。別の枠形状に差し替えないため、NORMAL／SELECTは正確に同寸・同窓である。
- v3は原画／配信用とも`900×5400`、四隅alpha=0、透明キャラ窓全体（`x=72..828 / y=150..5250`）の非透明ピクセル0を確認した。ゲームはv3を読込中。390×844相当でRAVEN通常とMIKA選択を確認済み。

### SELECTの主役感調整（2026-08-28）

- 最初のSELECTは金の後光が弱く、7枚の中で選択状態を見失う強さだった。B案の枠形状を変えず、遠い金ブルーム／近い金発光／高輝度の金リムの三層へ変更した。
- 発光のalphaを黒背景除去へ渡してしまうと、半透明の光が不透明な黄枠へ化ける。SELECTでは背景除去を再実行せず、alphaを保ったまま透明キャラ窓だけを打ち抜く専用処理に分けた。
- MIKA選択時に、NORMALの暗い黒鉄枠と明確に区別できる金リム・金発光を390×844相当で確認済み。外寸・窓寸法は不変。

### SELECT専用の描画素材へ再置換（2026-08-28）

- 上記の三層合成も、結果として「通常枠に電気を付けた」見え方になるため不採用。`championship-re-frame-b-select-master-v1.png`を、NORMALのB案を入力参照して生成したSELECT専用の正規原画として追加した。
- SELECT原画には、黒鉄のベベルへ入る金／白金の反射、物理的な金エネルギー溝、角とレール節の発光点まで描かれている。通常枠にCSSや後段の輪郭発光を足さない。
- 再生成スクリプトは、NORMALから検出した同じ物理枠のトリミング領域をSELECTにも適用する。これにより、イラストは別でも`900×5400`、外寸、透明キャラ窓、7枚固定配置を完全に揃える。透明窓全域のalpha=0を再確認済み。

### SELECT v4（ブラウザキャッシュ回避、2026-08-28）

- SELECT専用原画を繰り返し調整する過程で同じ`select-v3.webp`を上書きしていたため、Chromeが古い選択枠を表示し得る状態になった。見た目の採否とキャッシュの問題を混同しないため、最終候補は新しいURLの`championship-re-frame-select-v4.webp`へ切り替えた。
- v4はCSSや実行時の光処理ではなく、上記のSELECT専用正規原画から生成する同一仕様の素材である。NORMALは`normal-v3`のまま。両者の`900×5400`寸法と透明キャラ窓全域alpha=0を再検査済み。

### 縮小表示向けSELECTフレア（2026-08-28）

- 7枚横並びでは選択カード本体が約50px幅まで縮小される。v4の選択原画には星状フレアが存在していたが、NORMALと同じ物理枠だけへ切り出していたため、左右へはみ出す発光を失っていた。
- 選択原画を「縮小後も星が読める」専用のv2原画へ更新し、枠本体`select-v5`（`98×588`）と、背面フレア専用の`select-aura-v4`を分離した。背面フレアも生成画像由来の透過ラスタ素材であり、CSSの`box-shadow`や実行時の輪郭発光は使わない。
- Phaserでは本体枠・カードの座標・操作領域を不変とし、選択時だけ背面のフレア素材を同一中心へ表示する。キャラ窓へ光が1pxでも残らないよう、フレア素材側の窓は安全側へ広げ、NORMAL／SELECT本体／フレアの全窓alpha=0を走査確認した。
