# 旧案（参照禁止）: HELL RUNNER ローグライト能力システム 実装指示書

作成日: 2026-08-17
状態: **旧案・参照禁止。HELL RUNNER 2仕様へ置換済み**

> この文書は無印HELL RUNNERをローグライト化する前提で作られた旧案。無印は凍結済みのため実装に使わない。HELL RUNNER 2の正本は `docs/HELL-RUNNER-2ローグライト仕様書.md`。

## 1. 目的

タイトル画面で能力を解放・保存・選択する現行方式を、**走行中に経験値を集めて
その場で能力を選ぶローグライト方式**へ置き換える。

狙い:

- **保存データが消えても能力差が出ない。** 能力はラン内で取得するため保存不要
- **初回プレイヤーも同条件で戦える。** 現状は滑空が10000m到達で解放されるため、
  初心者は解放前にランキングへ挑むことになり、競技として不公平になっている
- **プレイ方針を選べる。** スコア狙いは吸引・コンボ、安定狙いは滑空・着地といった分岐

## 2. 基本ループ

1. 走行中に経験値オーブを取得する
2. 画面の経験値ゲージが進む
3. ゲージが満タンでゲームを完全停止する
4. 能力候補を3つ表示する
5. 1つ選ぶと取得・強化し、**既存の3秒カウントダウンを経て**再開する
6. レベルが上がるほど必要経験値を増やす
7. **レベル15で選択を終了する**（以降はレベルアップしない）

コインは従来どおりスコア用。**経験値オーブとは役割を完全に分ける。**

## 3. 能力プール

**8系統・合計21段階。そのうち15回しか選べない。** 6段階分を必ず諦めることになり、
ここでビルドが分岐する。

| # | 系統 | 段階 | 動かす既存の値 | 性格 |
|---|---|---:|---|---|
| 1 | 吸引範囲 | 4 | `pickupBonus` | スコア |
| 2 | コンボ倍率上限 | 3 | `Math.min(comboCount-1, 9)` の `9` | スコア |
| 3 | コンボ持続 | 3 | `COMBO_WINDOW = 1.2` | スコア |
| 4 | 滑空強度 | 3 | 落下時の重力倍率 `0.32` | 安全 |
| 5 | 着地の粘り | 3 | `PLAYER_LEDGE_SNAP_Y = 18` | 安全 |
| 6 | 押し戻し耐性 | 3 | `PUSHBACK_GROWTH = 360` | 安全（**要検証**） |
| 7 | 3段ジャンプ | 1 | `maxJumpsThisRun` を3へ | 機動 |
| 8 | 転生 | 1 | 死亡から1回だけ復帰 | 保険 |

### 3.1 段階値の初期案

**すべて暫定。デバッグモードで調整して実走で確定する（9節）。**

| 系統 | 初期値 | Lv1 | Lv2 | Lv3 | Lv4 |
|---|---:|---:|---:|---:|---:|
| 吸引範囲 (`pickupBonus`) | 0 | 20 | 40 | 60 | 80 |
| コンボ倍率上限 (段数) | 3 (+30%) | 5 (+50%) | 7 (+70%) | 9 (+90%) | — |
| コンボ持続 (秒) | 1.2 | 1.5 | 1.8 | 2.2 | — |
| 滑空強度 (重力倍率) | 0.32 | 0.28 | 0.24 | 0.20 | — |
| 着地の粘り (px) | 18 | 24 | 30 | 36 | — |
| 押し戻し耐性 (px/s) | 360 | 300 | 250 | 200 | — |

### 3.2 重要: 3段ジャンプと転生は1段階だけ

4段ジャンプと複数回復活は**作らない**。ユーザー判断で「ぬるくなる」ため除外済み。

### 3.3 能力にしてはいけないもの

**ジャンプ初速 `JUMP_VELOCITY` と重力 `GRAVITY` を能力で変えてはならない。**

地形生成が次の式で奈落の幅を決めているため。

```js
const singleRange = Math.min(760, Math.max(160, speed*JUMP_AIRTIME));
const doubleRangeBase = singleRange * DOUBLE_JUMP_RANGE_MULT;
```

ジャンプ性能を上げると**その先の地形が生成時点で緩くなり**、下げると**到達不能な奈落**が出る。
滑空は落下速度だけを変え地形生成に影響しないため安全。**この区別を必ず守ること。**

## 4. 選択回数の上限と候補不足

- **レベル15で選択を終了する。** 以降は経験値を集めてもレベルアップしない
- ゲージはレベル15到達時点で非表示にするか、満タン表示で固定する（見た目は実装者判断）

### 候補が3つ揃わない場合

短い系統から取ると、**最後の数回で選べる系統が2つ以下になる組み合わせが存在する。**
その場合だけ、以下の汎用強化で3枠を埋める。

- 経験値取得量アップ（残り回数が少ない時は価値が低いので、最後の穴埋めに適する）
- コイン価値アップ
- スコア加算（即時）

**汎用強化は、系統が3つ以上残っている限り出さないこと。** 常時出すと選択の重みが薄れる。

## 5. 経験値オーブ

### 5.1 生成

既存のコイン生成へ相乗りする。**新しい生成ロジックを作らない。**

```js
function addCoin(worldX, elevation, value, variant)
function spawnGroundCoins(seg)
function spawnGapCoins(gapStart, gapLen, prevH, isBig, doubleRange)
```

`variant` に経験値オーブを追加し、一定確率でコインの代わりに出す。

- 見た目はコインと明確に区別する（色・形）。取り違えるとビルドが崩れる
- 取得音もコインと分ける
- **出現頻度はコインよりかなり低くする。** 目安は9節で調整

### 5.2 配置のランダム化（要検証・後回し可）

吸引範囲が能力になるため、現在より縦方向にばらつかせる案がある。
**ただし試作の初回では実装しない。** 経験値カーブの体感を先に確定させるため。

将来入れる場合の注意: **奈落の上の高所へ置くと「取りに行って死ぬ」配置になる。**
吸引を取った人だけが安全に回収できる差になるので設計としては成立するが、
「これは取れない」と見て分かる高さに留めること。

## 6. 経験値ゲージとレベルアップ

- ゲージはHUDへ常時表示する。**HUDを圧迫しないこと**（縦長画面のため）
- 満タンで `state` をレベルアップ用の停止状態へ移す
- 必要経験値はレベルが上がるほど増やす。カーブは9節で調整

### 6.1 停止処理は一時停止の実装を流用する

**新しく停止処理を書かないこと。** 一時停止機能で作った仕組みをそのまま使う。

```js
const pauseFrozen = state==='paused' || state==='pauseCountdown';
```

ここへレベルアップ用の状態を加え、距離・物理・粒子・コウモリ・`animT`・BGMを止める。

### 6.2 【重要】入力の後始末を必ず行う

一時停止と**まったく同じ事故**が起きる。レベルアップの停止へ入る時、次の2つを必ず行う。

```js
clearJumpInput();
jumpCanBeCut = false;  // 停止中に指を離した扱いになり、再開時へカットが持ち越されるのを防ぐ
```

これを忘れると、**上昇中にレベルアップした人の大ジャンプが、再開時に勝手に小ジャンプへ変わる。**
奈落の上なら死につながる。`holdingInput` への直接代入は効かない（導出値のため）。

### 6.3 再開

**既存の3秒カウントダウン（`pauseTimer` / `pauseCountdown`）を共用する。** 選択後に
いきなり走り出させない。

## 7. 可視化

「あと2回しか選択が来ないが、3段ジャンプは必須だからここで取っておくか」という判断を
成立させるため、**残り回数と取得状況を常に確認できるようにする。**

| 場所 | 表示内容 |
|---|---|
| HUD（常時） | 経験値ゲージ + `Lv 7/15` のような到達レベルと上限。**最小限に留める** |
| 選択画面 | **残りの選択回数**、取得済み系統と現在の段階、各候補が何段階目か |
| 一時停止メニュー | 取得済みビルドの一覧（詳細はここで見せる） |

選択画面には「**この能力はあと何段階残っているか**」も出す。上限に達した系統は候補に出ない。

## 8. ランキングの扱い

**この大型アップデートの実装と同時に、現行ランキングをシーズン1として保存し、リセットする。**

- 現在の記録は「殿堂入り」として閲覧できる形で残す
- 新しいシーズンは別テーブルへ分ける（例: `runner_scores_s2`）

理由: コンボ倍率上限を能力化すると、**現在は全員が無料で持っている+90%が初期+30%へ下がる。**
同じ土俵で比較できなくなるため、記録を混ぜない。

### 8.1 【必ず読む】新テーブル作成時の落とし穴

**RLSポリシーだけでは足りない。GRANTを忘れると `permission denied` になる**（実際に踏んだ）。

```sql
grant select, insert on runner_scores_s2 to anon, authenticated;
grant usage on all sequences in schema public to anon, authenticated;
```

`id` が `generated always as identity` のため、シーケンスへの `usage` も要る。
詳細は `supabase-setup.sql` と `supabase-fix-permissions.sql`。

### 8.2 試作段階では送信しない

**スコアがどう変わるかは走ってみないと分からない。** 試作中はランキングへ送信せず、
体感が固まってからシーズン切り替えを実施する。

## 9. デバッグモードでの調整項目

`?debug=1` の DEV TOOLS へ `ROGUELITE` セクションを追加する。

**この節が本仕様で最も重要。** 決めるべき数値が多く、しかも「レベル15のビルドを試すには
20分走る」という構造のため、**調整用の近道が無いと実走確認が現実的に終わらない。**

### 9.1 数値スライダー

1. `ORB RATE` — 経験値オーブの出現率（コインに対する割合）
2. `XP BASE` — レベル1に必要な経験値
3. `XP GROWTH` — レベルごとの増え方（増分または倍率）
4. `LEVEL CAP` — 選択終了レベル（既定15）
5. 各系統の段階値（3.1の表の数値すべて）
6. `COPY ROGUELITE VALUES` — 確定値をJSONでコピー

**LAN内のHTTP接続ではClipboard APIが使えない。** ポータルの `PORTAL TUNER` と同じく、
COPY時は選択済みテキスト欄を必ず出して手動コピーへ落とせるようにすること。

### 9.2 【最重要】状態を即座に作る操作

**これが無いと調整が終わらない。** 特定のビルドを試すたびに走り直すのは非現実的。

| 操作 | 用途 |
|---|---|
| `GRANT XP` | 経験値を任意量その場で加算する |
| `FORCE LEVEL UP` | 即座に選択画面を出す。選択画面のレイアウト確認にも使う |
| `SET LEVEL` | 指定レベルまで一気に進める |
| **`GIVE ABILITY`** | **系統と段階を直接指定して付与する。3択を経ずにビルドを組める** |
| `CLEAR ABILITIES` | 取得済みを全部消して初期状態へ戻す |
| `BUILD PRESET` | よく試す構成を保存・呼び出しする（例: スコア型 / 安全型 / 無強化） |

`GIVE ABILITY` と `BUILD PRESET` があると、**「吸引Lv4＋コンボ上限Lv3」と「無強化」を
数十秒で比較できる。** これが押し戻し耐性の要否判断（3節の要検証項目）にも直結する。

既存の**距離ジャンプ**と**`NO FALL`** を併用すれば、任意の距離・任意のビルドを
即座に作って試せる。**新しく作らず、既存機能との併用を前提にすること。**

### 9.3 判定範囲の可視化

**数値だけでは効果を判断できない能力がある。** 該当する判定を画面へ描く切替を用意する。

| 切替 | 描くもの | なぜ必要か |
|---|---|---|
| `SHOW PICKUP RANGE` | 吸引範囲 (`hRadius` と縦の許容幅) | 吸引Lv1とLv4の差が見た目で分からない |
| `SHOW LEDGE SNAP` | 着地の粘りの許容ゾーン | 「際どい着地が決まった」のが能力のおかげか運か区別できない |
| `SHOW PUSHBACK` | 押し戻し量と復帰速度の数値 | **押し戻し耐性が有効かどうかの判断材料そのもの** |

特に押し戻し耐性は「360→200で何が変わるのか」が体感しにくい。
**壁に当たった回数と、その時に失った距離の合計**を出すと判断できる。

### 9.4 計測と統計

カーブ調整の主指標。**理論値ではなく実測を出すこと。**

| 表示 | 内容 |
|---|---|
| `LEVEL LOG` | 各レベルに到達した**時刻と距離**の一覧。カーブ全体を一度に見る |
| `LAST LEVEL` | 直近のレベルアップまでにかかった時間と距離 |
| `ORB RATE (実測)` | 1分あたりのオーブ取得数、コイン取得数との比 |
| `COMBO` | 現在のコンボ数と**実効倍率**。コンボ系能力が効いているかの確認 |
| `SCORE BREAKDOWN` | **スコアの内訳（距離ぶん / コインぶん）** |
| `POOL` | 各系統の残り段階数と、選択可能な系統数 |

`SCORE BREAKDOWN` は**シーズン切り替えの判断に直結する**。コンボ倍率上限を能力化すると
初期値が+90%から+30%へ下がるため、コインぶんが実際どれだけ減るかをここで測る（8節）。

`POOL` は、4節で述べた「候補が3つ揃わない」状況が実際に起きるかの確認に使う。

`LEVEL LOG` は**まとめてコピーできるようにする**。ランごとの比較に使うため。

### 9.5 再現性（任意・後回し可）

`SEED` を固定して、地形とオーブ配置を同じにできると**ビルドの比較が正確になる**。
同じ地形で「吸引あり / なし」を走り比べられる。

ただし `generateTerrain` とコイン生成の乱数をすべて差し替える必要があり、
**地形生成にはテストが無いため危険度が高い。** 骨組みが安定してから別作業として検討する。
試作の初回では実装しない。

### 9.6 パネルの整理

DEV TOOLS には既に音量4種・`JUMP HEIGHT`・`PAUSE BUTTON SIZE`・`NO FALL`・録画などがある。
ここへ本節の項目を足すと**縦に収まらなくなる。**

- `ROGUELITE` セクションは**折りたたみ可能**にし、既定は閉じておく
- 携帯ではタイトル画面のPLAYを塞がないこと（既存の初期縮小の方針を維持）
- 既存セクションのレイアウトを崩さない

### 9.7 調整の目安

`BASE_SPEED = 640` px/s、距離は `distance/9` m なので **秒速71m**。

| 到達距離 | 所要時間 |
|---:|---:|
| 2,500m | 35秒 |
| 10,000m | 2分21秒 |
| 20,000m | 4分41秒 |
| 100,000m | 20分42秒 |

初期の目標感触:

- **1回目のレベルアップは30〜40秒（約2,000〜2,800m）**。早めに1回やらせて仕組みを理解させる
- 2〜5回目は1分前後
- 以降は1分30秒〜2分へ広げ、20分前後のランで15回に達する配分

**必要経験値を増やすほど選択の間隔が空き、ランを伸ばす動機になる。** ここは実走で決める。

## 10. 既存仕様との関係

### 10.1 タイトル画面の能力選択は残す（試作段階）

**最終的には廃止して完全移行するが、試作では残して並行させる。** 比較対象が必要なため。

移行時に廃止するもの:

- タイトル画面の能力選択画面
- `localStorage` の解放状況（`unlocked`）
- 2500m / 5000m / 10000m の解放通知

### 10.2 死神は能力にしない

**20000mの「デスイーター降臨」はステージギミックとして残す。** 背景・BGMの段階変化と同じく、
到達の手応えそのものになっているため。能力の吸引範囲とは別物として扱う。

なお現在の吸引ボーナスは `kaiokenActive ? 70 : 0` で実装されている。
**能力の吸引範囲とデスイーターのボーナスは加算にするか排他にするかを決めること**
（推奨: 加算。デスイーター到達が能力ビルドと噛み合う爽快感が出る）。

### 10.3 ライバルは触らない

演出のまま。能力候補へ入れない。

### 10.4 旧「十倍界王拳の選択式」との区別

禁止されているのは、**旧十倍界王拳をタイトル画面の能力選択へ戻すこと**。
本件は走行中に停止して3択から取得する別方式であり、旧方式への復帰ではない。

## 11. 保存方針

- **取得した能力とレベルはそのラン限り。保存しない**
- ベストスコア、音量設定は従来どおり保存する
- 恒久的にプレイへ影響する要素を新たに保存しない（ランキングの公平性のため）

## 12. やってはいけないこと

- `JUMP_VELOCITY` / `GRAVITY` を能力で変える（3.3）
- `SINGLE_JUMP_APEX` と奈落生成の上限を変える
- 停止処理を新規に書く（6.1の既存実装を流用する）
- `holdingInput` へ直接代入する（導出値。`clearJumpInput()` を使う）
- 汎用強化を常時候補に出す（4節）
- 試作段階でランキングへ送信する（8.2）
- `games/temple-run-clone.html` は約6.5MB。全体読込・全体書換え・フォーマッタは禁止。
  500文字超の埋め込み行を避け、部分置換だけで編集する（`AGENTS.md`）
- コメントは日本語で「なぜそうしたか」を書く

## 13. テスト

`tests/debug-mode.spec.js` へ追加する。

1. 経験値オーブを取得するとゲージが進む
2. ゲージ満タンでゲームが停止し、距離・座標・粒子が進まない
3. 候補が3つ表示され、系統が重複しない
4. 上限に達した系統が候補に出ない
5. **レベル15に達したら、以降はゲージが満タンでも選択が出ない**
6. 選択後は即再開せず、3秒カウントダウンを経て再開する
7. **上昇中にレベルアップしても、再開後に大ジャンプが小ジャンプへ変わらない**（6.2の担保）
