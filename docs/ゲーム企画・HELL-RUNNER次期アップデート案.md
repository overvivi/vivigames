# ゲーム企画・HELL RUNNER次期アップデート案

作成日: 2026-08-17  
状態: **企画整理段階。実装順・詳細仕様は未確定**

## 1. 新作ゲーム候補

### 1.1 複合型音楽ゲーム

音楽生成AIで制作したオリジナル曲を使い、同じ1曲を複数の遊び方で楽しめる音楽ゲーム。

候補モード:

- 太鼓系: 画面を流れるノーツを2種類程度の入力で叩く
- ポップン系: 複数レーンへ降るノーツを担当キーで処理する
- DDR系: 上下左右のステップ入力で遊ぶ
- A Dance of Fire and Ice系: 曲のリズムに合わせ、少数の入力で軌道を進む

共通化したい要素:

- 1曲に対し、遊びたいモードと難易度を選べる
- 曲情報、BPM、拍子、小節位置を全モードで共有する
- スコア、コンボ、判定、リザルトの基本部分も共通化する
- 各モードの譜面データだけを分離し、曲追加時の作業量を抑える

先に決めること:

- 譜面を手動作成するか、音源解析で下書きを自動生成するか
- PCキーボード、携帯タップ、ゲームパッドのどこまで対応するか
- モードごとに譜面を個別制作するか、共通タイミングデータから変換するか
- 音源の利用条件、容量、読み込み時間

### 1.2 AIストーリー生成型テキスト放置ゲーム

Your Chronicleのように、テキスト・選択肢・数値成長を中心に進む放置ゲーム。AIがプレイヤーの進行状況に応じて物語を生成する構想。

基本ループ案:

1. 行動を選択する
2. 時間経過で資源・能力・仲間・物語フラグが増える
3. 条件達成で新しい選択肢や地域が開く
4. 節目でAIが現在の状態を材料にイベント文章を生成する
5. 周回・転生で一部能力を持ち越し、別展開へ進む

AI利用時の重要方針:

- 数値計算、報酬、解放条件はゲーム側で確定し、AIには変更させない
- AIは文章、演出、選択肢候補など物語表現を担当する
- 世界設定、登場人物、禁止事項、現在のフラグを構造化して渡す
- API障害やオフライン時にも、固定イベントで進行できるようにする
- APIキーをブラウザへ直接埋め込まない。利用する場合は安全なサーバー側処理が必要
- 生成コスト、待ち時間、不適切表現、物語の矛盾への対策が必要

小さく始める場合:

- 最初は固定シナリオ＋AI生成の短いフレーバーテキストだけにする
- AIなしでもゲームとして成立させ、後から生成範囲を広げる

### 1.3 テトリスブラスト

既存のテトリスを土台に、Vampire Survivors風の能力選択と連鎖破壊を加えるゲーム。

基本ループ案:

1. 通常のテトリスでラインを消す
2. 経験値または一定ライン数でレベルアップする
3. 3択から能力を1つ選ぶ
4. ミノ・消し方・連鎖へ特殊効果が追加される
5. 能力の組み合わせで毎回異なるビルドを作る

能力例:

- T字ミノで1列消去すると、追加で着地点周辺を円形爆破する
- 4ライン消去で隣接列へ追加ダメージ
- 一定コンボごとに邪魔ブロックをまとめて破壊
- 特定ミノの出現率上昇
- ホールド回数追加
- 爆発半径、連鎖回数、経験値獲得量の強化

設計上の注意:

- 円形爆破をマス単位でどう定義するか決める
- 爆破後に浮いたブロックを落下させるか、その場へ残すか決める
- 能力選択中は盤面時間を完全停止する
- 通常テトリスの読み合いを壊さないよう、能力なしでも成立する土台を先に完成させる

## 2. HELL RUNNER短期修正案

### 2.1 転生時の接地バグ修正（実装済み）

症状:

- 転生後、プレイヤーが地面へ半分埋まる場合がある
- 逆に地面から浮いて見える場合がある

調査・修正方針:

- 転生先の足場上面と `player.y`、`player.groundH`、描画上の足先位置を同じ基準で計算する
- 転生直後に `grounded = true` とするだけでなく、足先を足場上面へ明示的にスナップする
- 平地、段差上、画像地面、各画面サイズで確認する
- 3秒カウント中と再開直後の両方で位置が変化しないことをテストする

### 2.2 転生確認画面（実装済み）

死亡した瞬間に自動転生せず、いったん確認画面を表示する。死亡直前の連打が選択へ誤爆しないよう、画面遷移ボタンは表示後900msロックする。

表示候補:

- `転生を発動しますか？`
- 転生を使用して続行
- RETRY
- HOME / HELL RUNNER TOP

目的:

- 死亡直後に休憩できる
- ステージ序盤で転生を消費したくない場合、RETRYを選べる
- 意図せず転生を使うことを防ぐ

確認事項:

- 「チェックボックス」は選択状態を保持するUIではなく、確認画面または確認ボタンの意味として整理する
- 転生を選んだ場合だけ `usedReincarnate = true` にする
- RETRYとHOMEを選んだ場合は転生を未使用のまま、そのプレイを終了する
- 確認画面中はゲーム・演出・BGM・入力を停止する
- 転生を選んだ後は既存の3秒カウントを経て再開する

## 3. HELL RUNNER 2案（既存版とは分離）

### 3.1 目的

既存HELL RUNNERを上書きせず、ゲーム部分を流用した独立作`HELL RUNNER 2`で、プレイ中に経験値を集めて
能力を選ぶローグライト方式を導入する。詳細な確定仕様と素材制作順は
`docs/HELL-RUNNER-2ローグライト仕様書.md`を正本とする。

狙い:

- 初回プレイヤーでも、そのプレイ中にランキング用ビルドを作れる
- キャッシュや保存データが消えても能力差が発生しない
- 能力を取る順番でプレイ方針が変わる
- 新能力を後から追加しやすくする

### 3.2 基本ループ

1. 走行中に経験値オーブを取得する
2. 画面内の経験値ゲージが上昇する
3. ゲージ満タンでゲームを完全停止する
4. ランダムな能力候補を3つ表示する
5. 1つ選ぶと能力を取得・強化し、3秒カウント後に再開する
6. レベルが上がるほど必要経験値を増やす

コインは従来どおりスコア用として残し、経験値オーブとは役割を分ける。

### 3.3 現在の要素を能力候補へ再構成する案

| 要素 | 能力化した場合の役割例 |
|---|---|
| 3段ジャンプ | 最大ジャンプ回数を2回から3回へ増やす |
| 滑空 | 落下中長押しで落下速度を抑える |
| 転生 | 1回だけ死亡から復帰できる。死亡時は確認画面を出す |
| 死神 | コイン吸引やスコア特化能力として取得する |
| ライバル | 取得後に明確な追加効果を持たせる。内容は別途決定 |

プレイ方針の例:

- スコア重視: 早めに死神を取得してコイン回収を強化
- 初心者・安定重視: 転生や滑空を優先
- 機動力重視: 3段ジャンプを優先
- ライバル特化: 新しい追加効果を軸にビルドを組む

### 3.4 ライバル能力の案

現在は演出・お笑い要素が中心なので、能力候補へ入れる場合は実利を追加する。

候補:

- ライバルが先のコインを回収し、一定割合をプレイヤーへ渡す
- ライバルが一度だけ奈落の先へ橋または安全な足場を作る
- ライバルが経験値オーブの取得範囲を広げる
- ライバルが近くにいる間、スコア倍率または経験値倍率が上がる
- ライバル落下時に周囲の経験値オーブを回収する

### 3.5 能力選択画面の要件

- 3択を基本とする
- 選択中はプレイヤー、距離、地形、敵、粒子、BGM進行を停止する
- 携帯で3枚が押しやすく、説明文が読める配置にする
- 同じ能力を再取得した場合に強化するか、一度だけ出現するかを能力ごとに定義する
- 候補が足りない場合の代替として、回復・スコア・経験値などの汎用強化を用意する
- 選択後はいきなり再開せず、既存の3秒カウントを共用する

### 3.6 保存方針

- プレイ中の能力とレベルは、そのラン限りとする
- ランキング挑戦に影響する恒久能力は保存しない
- ベストスコア、音量設定、必要ならチュートリアル確認済みだけを保存する
- 将来恒久要素を追加する場合も、ランキングの公平性へ影響しない外見・図鑑などを優先する

### 3.7 旧仕様との区別

禁止されているのは、旧「十倍界王拳」をタイトル画面の既存アビリティ選択へ戻すこと。
今回の案は、**ラン中にゲームを停止し、その場で表示される3択ポップアップから能力を取得して、
選んだ時点以降だけ発動するローグライト方式**であり、旧方式への復帰ではない。

死神をこの新しいラン内能力へ再構成することは可能。ただし、現在の20000m自動発動を同時に残すか、
新方式へ完全移行するかは大型アップデートの詳細仕様で決める。

### 3.8 確定した能力スロットとレアリティ方針

能力は、効果を文章で読まないと体感しにくい細かな物理補正ではなく、取得の有無でプレイ方法が
明確に変わるものを優先する。能力スロットは次の3系統とする。

- メイン（RARE・黄）: 2枠。3段ジャンプ、滑空、転生の3種類から2種類だけ取得できる
- 補助（COMMON・青）: 3枠。コイン得点、コンボ、経験値などから3種類だけ取得できる
- 特殊（LEGEND・虹）: 1枠。通常ルールを一つだけ変更する能力から1種類だけ取得できる

メイン・補助とも、枠が埋まった後は未取得の同系統能力を候補から除外する。取得済み能力の
レベルアップは引き続き候補へ出る。転生はレベル制にせず、取得時点で1回使用可能にする。

主能力がなくても2段ジャンプだけで十分に長距離を攻略できる難易度を維持する。そのためRAREを
毎回保証せず、序盤に運良く完成するラン、主能力を後回しにして得点補助へ賭けるランの両方を許容する。
ライバルは能力候補へ入れず、現在の不安定ですぐ落下することもあるギャグ系ステージギミックとして残す。

レベルアップは1回目だけ早期に体験できるようにし、2回目以降の必要経験値を大きく増やす。
100000mでもビルドは未完成、200000mでも全能力は取得できず、何種類かを切り捨てる状態を目標とする。

### 3.9 確定した特殊能力案

特殊スロットは1枠なので、次の能力は同じランで併用できない。

- デスイーター: 装備中および取得後に装備する補助能力の最大レベルを1段階増やす。取得だけで
  即時強化せず、例として通常上限Lv.5を、その後のレベルアップでLv.6まで育てられるようにする
- スロット解放: メインスロットを2枠から3枠へ増やし、3段ジャンプ・滑空・転生を全て取得可能にする
- 修羅: 取得時点から通常の緩やかな速度上昇を無視し、固定速度へ切り替える。試作初期値は速度1.5倍、
  取得後に得た距離点とコイン点だけ1.10倍。速度と倍率はデバッグ試遊で確定する
- 変換器: 取得時点からコインを見た目も含め経験値オーブへ変換する。コイン数をそのままXPへ置換せず、
  出現数・間隔・XP価値を専用調整する。直接コイン点とコンボを失う代わりにビルド完成を早める
- ギャンブラー: 取得後はレベルアップで停止せず、有効な能力から自動取得する。満杯スロットの未取得能力、
  最大レベル能力、他の特殊能力は抽選しない。試作初期値は取得後の得点1.12倍とし、実測で調整する

修羅とギャンブラーの得点倍率は取得前の得点へ遡って掛けない。修羅は過去に廃止した通常選択式の
修羅モードを戻すものではなく、極低確率の特殊スロット能力として高リスク・高得点へ再構成する。

### 3.10 補助能力と育成完了後

補助能力の初期候補は、コイン得点倍率、コインコンボ倍率、コンボ持続時間、経験値倍率、
経験値オーブ吸引とする。コイン配置は現在より出現頻度を下げて間隔を広げ、補助能力なしで
常時最大コンボにならないよう調整する。コンボ持続時間は試作初期値として基本1.0秒、
1レベルごとに+0.15秒、通常Lv.5で1.75秒、デスイーターの限界突破Lv.6で1.90秒を候補とする。

レベルそのものには上限を設けない。全スロットが埋まり、全取得能力が最大レベルになった後は、
能力選択画面を表示せず、内部でコイン報酬を抽選して即座にスコアへ加算する。幸運報酬を引いた場合は
プレイヤー頭上へ `Lucky!` などを表示する。必要経験値は完成後も増加し続け、経験値特化ビルドは
他のビルドよりコイン報酬の抽選機会が少し増える程度にする。

変換器の完成後報酬は、通常プレイの10000mあたり平均コイン得点を実測して決める。初期目標は、
変換器によって失う直接コイン得点の70～80%程度を完成後の無限レベル報酬で回収できる値とする。
残りの価値はビルドを早く完成できる利点で補い、変換器が常に得点上も上位互換にならないようにする。

通常の能力3択中だけゲームを完全停止する。選択後の3秒カウントは使わず、画面復帰後0.5～0.8秒程度の
短い入力可能な静止時間を試作し、現在位置を把握して再開できるようにする。ギャンブラー取得後と
全能力完成後はレベルアップで停止しない。

能力選択画面、通常プレイ中の能力スロット、経験値バーの完成予想図は
`docs/mockups/hell-runner-roguelite-ui-concept.png`。通常画面は上部HUD直下に細い経験値バーを置き、
6スロットを左右端へ小さく分けて中央視界を確保する。選択画面は携帯で読みやすい縦3枚とし、
カード1タップで即時決定する。

## 4. 推奨する実装順

1. 転生時の接地バグを再現・修正する
2. 転生確認画面を追加する
3. 既存テトリスを遊べる土台として評価する
4. 小規模なテトリスブラスト試作を作る
5. HELL RUNNERの経験値・レベルアップだけを能力1〜2個で試作する
6. 試遊結果を見て、既存能力の全面移行と死神の仕様変更を判断する
7. 音楽ゲームは共通譜面形式を先に設計する
8. AI放置ゲームは固定シナリオ版を先に作り、AI生成を後付けする

短期修正と大型アップデートを同時に進めると転生処理が競合するため、まず接地バグと転生確認を完成させ、
その後にレベルアップ能力システムへ統合するのが安全。
