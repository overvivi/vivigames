## 2. 現在の仕様（変更後）

### 2.1 二つの遊び方と遺灰（通貨）

**葬送**（32波で終わる）と **無限の葬送**（底なし）で、敵の強さ・遺灰の入り方・終わり方を分けた。
`data.js` の `D.MODES` 一箇所で調整できる。エンジンでは `run.rule` で引く。

| | 葬送 | 無限 |
|---|---|---|
| 終わり | 第32波の主で勝利。「さらに深く」は廃止 | 終わらない。勝利画面に入らない |
| 深度 I〜V | 選べる | **選べない**（常に0。到達波で公平に競うため） |
| 雑魚の硬さ | 基礎 ×1.25、一波ごと +9% | 基礎 ×1、一波ごと +7.5% |
| 32波より先 | — | 主も雑魚も **一波ごとに ×1.08**（`deep`） |
| 主の硬さ | ×1.2 | ×1（32波より先は `deep` が掛かる） |
| 射撃間隔 | ×0.8（よく撃つ） | ×1、速さの上限 2.2→3.5 |
| 被弾の重さ | ×1.2（弾・接触・柱・光線） | ×1 |
| 冠付き | 4波から2波おき、17波から一波に2体 | 9波から3波おき、32波より先は毎波、25波から2体 |
| 頭数の上限 | 56 | 120（湧く間隔も .22→.12 まで詰まる） |
| **遺灰** | **主からだけ** 25 ×（1＋深度×0.25）。深度Iで100、Vで200／踏破 | **落とし物だけ** 2% |

- 冠付きの遺灰は両方とも廃止（冠付きは難しさの役だけ）
- 無傷の波の +2 遺灰も廃止（波ごとの配給が主の価値を薄めていたため）。無傷の回数は記録に残る
- 聖餐（取れる強化が尽きたとき）の +10 は残した
- 落とし物は `run.pickups` に入り、触れて拾う。波をまたいで床に残り `D.ASH.life`（32秒）で朽ちる
- 採取（`stats.harvest`）が両方に掛かる
- 記章（実績）の報酬に `D.ASH.medal`（0.2）を掛ける。**画面の表示も実額に直した**（前は額面のまま出ていた）
- 記録: `profile.abyss` ＝ 無限の最深（タイトルと墓碑に出す）。`profile.best` は両方合わせた最深で、実績判定に使う。墓碑の各行は `endless` を持ち「無限」と出る
- 深度の解放（`clearedDifficulty`）は葬送の踏破だけで進む

全装備の解放に必要な額は 1590 遺灰（弔具820 + 仮面770）。

### 2.2 スコアと連祷 — 廃止

- **得点（score）を一切加算しない。** 記録の保存形式には `score` フィールドが残っているが常に 0。互換のため消していない
- **連祷（コンボ）は廃止。** HUD の表示、倍率、最長記録、結果画面の行をすべて削除
- 墓碑の並び順は **到達波 → 時間** になった（得点を見ない）
- 理由: 武器ごとの連続撃破のしやすさが、そのまま収入差になっていた。原作もコンボを持たない

### 2.3 進化と共鳴 — 目標選択を廃止

- **「追い求める禁忌」「共鳴を目指す」の選択UIを全廃。** 支度画面の select、`guidance-preview`、強化画面の「目指す禁忌：…」、ビルド画面の「この禁忌を目指す」ボタン、共鳴の二段階の導き、3波ごとの材料保証
- `drawChoices()` を作り直した:

```js
// 条件の揃った禁忌進化は待たせず候補へ出す。普通の強化の枠は一つ残す。
const ready = this.eligibleEvolutions();   // シャッフル
for (const e of ready.slice(0, Math.max(1, this.stats.choices - 1))) choices.push(e.id);
// 残り枠を通常の強化で埋める
```

- **旧仕様のバグも消えた**: 共鳴を目標にすると、条件の揃った他の進化が候補から締め出されていた
- 共鳴は元から自動発現（進化2種が揃うと勝手に開く）。ここは変えていない
- エンジンの `guidancePlan()` `setGuidance()` は削除。`run.guidance` / `initialGuidance` は空文字で残置（保存形式の互換）

### 2.4 削除した機能

| 機能 | 理由 |
|---|---|
| 試射室 | 「このビルドは強いか」を走る前に外で答えてしまう。完成時の快感を前借りする |
| 墓碑の保存枠（6件） | 強いビルドを保存して使い回せると、毎回組み直す前提が壊れる |
| 追憶の祭室・連戦 | ボスを練習できると、走りの中の緊張が抜ける |
| 種子の指定・同種子再挑戦 | 同じ悪夢をやり直せるのはローグライトの逆 |
| 刻んだ道程・直近の被弾 | 開発の計測データをプレイヤー画面に出していただけ |
| 日替わりの悪夢 | 固定装備・祭壇なしで、本質と別のゲームになっていた。跡地に無限の葬送を置いた |
| 墓碑の詳細 | 一覧（到達波・弔具・刻印）は残した |

`source/trial.js` は削除。関数31個を撤去した。

### 2.5 画面

- 画面下の操作説明とトグルを削除。**照準・射撃の切替は元から設定パネルにある**ので重複だった
- 盤面の右上に休息ボタン `❙❙`（`#pause-frame`）。上バーの `#pause-top` は撤去済み
- 勝利画面は `THE GOD IS SILENT` を大見出し（最大58px）。日本語見出しと詩と末尾の説明を削除

### 2.6 スマホ操作

- **タイトルから図鑑まで、縦持ちの端末では画面ごと横向きに描く。** `#app` を
  `transform:rotate(90deg) translateY(-100%)` で回し、幅に `100dvh`・高さに `100dvw` を当てる。
  端末の回転ロックを外さなくても、スマホを横に倒せば正しい向きで読める
- 寸法は `--vw` / `--vh` の変数に通してあり、回転時だけ中身を入れ替える。CSSで `100dvh` や `100vw` を直接書かないこと
- 回転中も画面幅は端末の短辺のままなので、メディアクエリ側で辻褄を合わせてある。**クラスでの上書きはしていない**
  （特異度が上がって並び順の意味が壊れ、短い横画面用の `#game-frame{width:100vw}` が勝って盤面がはみ出した）
  - 細い画面用 `@media(max-width:Npx)` → `(max-width:Npx) and (orientation:landscape), (max-width:Npx) and (pointer:fine)`
    （回転中は必ず portrait かつ coarse なので、その組み合わせだけ外れる）
  - 横持ちの端末用 `@media(max-height:560px) and (orientation:landscape)` →
    `, (max-width:560px) and (orientation:portrait) and (pointer:coarse)` を足す
    （回すと器の高さは端末の短辺になるので max-height ↔ max-width が入れ替わる）
- 回転前の縦向けレイアウト（`padding-top:10vh` 等）は撤去済み。縦持ちは必ず回るので、横持ちと同じ指定を使う
- **iOS Safari は向きの固定に対応しない。** `screen.orientation.lock()` は未実装で、
  manifest の `orientation:landscape` も無視される。だから中身を回す以外に手が無い
- 回転中は指の横移動が画面の縦移動になるので、`ui.js` の `alongX()` が `clientX`/`clientY` を切り替える
- 盤面は常に横長になるため、横持ち用に書いていた詰め指定は `@media(pointer:coarse)` へ広げてある
  （`max-width:600px` の縦向けレイアウトが回転後にも当たってしまうため）
- **なぞって移動**: 触れた点が支点。不感帯9px、74pxで最大速のアナログ。指を戻すと支点が追従
- **なぞる面は盤面ではなく戦闘画面全体**。横の余白で滑らせても端のスワイプ戻りが起きない
- **叩いて跳躍**: 230ms以内・ずれ15px以内
- **跳躍と回避は右下のボタン**（左が回避、右が跳躍）。実機で「右から左へ折り返すと回避が暴発する」と分かったため、払い判定は撤去した
- 大奇跡は中央下。ビルドの確認は指の置き場なので戦闘中は出さず、休息から見る
- 手元のボタンは盤面の下 20.7%（地面 world 428/540 より下）の帯に高さを比率で収める。地面との間に12〜13pxの余裕、ボタン高47〜54px
- 休息ボタンは盤面の右上。HUDの遺灰と重ならないよう `.score-block` に右余白を取ってある
- 多点対応。左指で移動しながら右指でボタンを押せる
- ボタンの上から始まった指はそのボタンのもの（`e.target.closest('button')` で判定）
- 強化選択は横並び・上寄せ。**出現後360msはタップを受け付けない**（誤タップ防止）
- 定数は `ui.js` の `TOUCH` 一箇所

### 4.1 難易度 — 葬送と無限の作り分けまで実装済み（2026-09-23）

実施: 初撃と攻撃間隔の短縮、出現数と耐久の伸び、葬送と無限の作り分け（§2.1）。

**測定は `tests/difficulty.cjs`。** 自動操作は0.5秒先までの弾・柱・光線・接触を読んで一番当たらない動きを選ぶ。
既定は人並み（0.2秒ごとに判断、近くの弾だけ見る）。`sharp` で上手い人の上限。`endless` で無限。

```
node projects/blood-choir/tests/difficulty.cjs 0 32 none            # 葬送 深度I 祭壇なし
node projects/blood-choir/tests/difficulty.cjs 4 32 full            # 葬送 深度V 祭壇最大
node projects/blood-choir/tests/difficulty.cjs 0 90 full endless    # 無限 祭壇最大
```

実測（人並み・seed 5〜7本）:

```
葬送 深度I  祭壇なし   7本中5本が第13〜17波で倒れる
葬送 深度I  祭壇最大   5本中4本が踏破、1本は第32波の主で倒れる
葬送 深度V  祭壇最大   5本中3本が第12〜14波で倒れる
無限        祭壇なし   5本中4本が第33〜68波で倒れる（第32波の主が最初の壁）    遺灰 平均203
無限        祭壇最大   5本中4本が第68〜78波で倒れる（1本は第100波まで生存）   遺灰 平均377
```

自動操作は弾読みが人より正確なので、人の到達はこれより浅いはず。**実機で遊んだ感触で `D.MODES` を詰める。**

### 4.2 弾の相殺 — 実装済み（2026-09-23）

自弾にも敵弾にも `guard`（耐久）があり、ぶつかると**耐久の低い方が砕ける**。
勝った側も一つ削れる。総当たりを避けるため64pxの格子で近い弾だけを見る（`collideBullets()`）。

- 自弾 `guard = 1 + min(4, stats.pierce)` — 貫通を積むほど弾幕を押しのけられる
- 敵弾 `guard = 1 + floor(wave/12) + (主なら +2)` — 深く潜るほど、主の弾ほど硬い
- 相殺すると小さな火花（`clash` イベント → 骨色と橙の粒）

効果（深度1・祭壇なし）: 第5波の被弾 23→10、第6波 43→28、第8波に入る時点の残生命 25→50。
主の弾は耐久3なので素の自弾では消せない。

残件: 「敵弾を抜けるたび自弾の威力+25%」（原作のアセンション）は未実装。
自弾の耐久を上げる専用の強化・祭壇も未追加（今は貫通に相乗り）。
